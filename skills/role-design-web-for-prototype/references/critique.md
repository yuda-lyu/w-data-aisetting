# 截圖評審：看成品，不看程式碼

**為什麼要這一步**：檢查清單全過，只證明沒有出現被禁止或壞掉的東西，不證明頁面好。程式碼是你寫的，你會把意圖讀進去；截圖只呈現真的在那裡的東西。**問題只要出現在截圖裡就是真的，不論程式碼怎麼說。**

**數據與評分架構出處**：[taste-skill](https://github.com/Leonxlnx/taste-skill)（MIT）的評審規則（以 Awwwards 評審權重為準）與其盲測紀錄。

## 1. 截圖

- **三個寬度**：1440、768、390。每個寬度都截首屏與整頁（整頁太長時分段截）。
- **工具**：用手邊可用的瀏覽器工具——專案或技能根已有 Playwright 時用 `page.screenshot({ fullPage: true })`；否則用 Chrome／Edge 無頭模式（`--headless=new --screenshot=<檔> --window-size=1440,900 <網址或 file:///絕對路徑>`，此法只截視窗大小，整頁要靠調高視窗高度或分段捲動）。沒有任何截圖工具時，在回報中直說評審未能執行，不要假裝看過。
- **落點**：截圖一律存在 `./tmp/<案名>/shots/`，檔名帶寬度與輪次（`r1-1440-fold.png`、`r1-390-page-2.png`）。
- **先等字體與圖載入**：截到後備字體的截圖，判斷的一切都不是真的——先修字體載入。
- **有動效時**：動效做完後再截一輪，逐張找沒出現的內容（沒觸發的揭示會留下空白帶）；需做無障礙時（主檔〈受眾分級〉），另截一輪 `prefers-reduced-motion: reduce` 的畫面，確認內容完整。
- **每一張都打開看**（用讀圖工具），不是只看首屏。

## 2. 頁面：十四道觀看

依序開：桌機首屏 → 桌機整頁 → 手機首屏 → 手機整頁。每一道分開看，不要混在一起。

1. **一秒，再五秒**：瞄一眼移開，看到了什麼？答案應該只有一個——一個字、一張圖、一個物件。答案是「一個網站」，代表沒有焦點。再用陌生人的身分看首屏五秒：說得出這是什麼、給誰、下一步做什麼嗎？標題要捲下去才懂，它就不是標題。
2. **瞇眼**：模糊到文字變成灰條。頁面應該化成兩三塊大小差異明顯的量體；很多相似的小塊代表全部都是中等、沒有東西領頭。
3. **遮住 logo**：這個首屏能不能屬於競爭者、或屬於另一個行業？把名字和標題裡的名詞換掉仍然成立，頁面就沒有概念——回 Step 3 的概念句。再往下捲：概念有沒有走到價格、FAQ、頁尾，還是第一屏之後就變成罐頭區塊？
4. **邊緣**：沿著每塊文字的左緣往下看，數有幾個不同的 x 位置。構圖過的頁面是兩到三個、刻意重用；六個代表東西是一個一個放上去的。
5. **空間與版框**：相關的近、不相關的遠？段落間距明顯大於段落內任何間距？有沒有意外的空白（破洞）而不是決定的空白（留白）？破洞通常在短欄旁或被拿掉的裝飾下面。再看版框：左右邊距一樣嗎？有沒有哪段文字在一半、另一半空著？有沒有超過半屏高的一段什麼都沒有？讀者在任何細節之前先說出這些（「被推到左邊」「莫名其妙的空白」）。
6. **字**：內文到標題的跳躍夠果斷嗎（三倍以上）？看到超過五種尺寸嗎？有標題最後一行只剩一個字嗎？有段落寬過約 75 字元（中文用截圖目測，一行過長就是過長）或置中超過三行嗎？
7. **色**：說出比例——哪個顏色佔最多面積、哪個輔助、強調色在哪？出現在十個地方的強調色沒有意義；只在唯一的動作和一個細節上的強調色才代表「這裡」。
8. **圖**：每張圖都在做事嗎（展示東西、交代地方、證明主張）？裁切比例一致嗎？有沒有灰框、被拉伸的照片、用灰條拼成的假畫面？照片是同一種光、同一種調色，還是圖庫混搭？只有繪圖或只有字的頁面，放在有真實照片的頁面旁邊看起來像沒做完。
9. **重複**：為每段的構圖寫一個詞（分割、清單、滿版、格狀、陳述、索引……）。同一個詞連續兩次、或全頁三次，就是模板在露臉。
10. **手機**：手機畫面是自己的構圖（自己的裁切、自己的斷行），還是桌機被擠小？首屏仍是一件清楚的事嗎？
11. **飽滿**：一屏一屏看桌機截圖。每屏是構圖過的海報，還是兩側空地中間一窄欄小字？有沒有一句陳述佔三屏？樸素的頁面不等於克制的頁面：會被誤認成未完成線框稿的（灰形狀、灰字、一窄欄），就是蓋得不夠。一個母題放大填滿整屏卻沒有任何可讀的東西，再大膽也是破洞。
12. **實質**：需求要的每一段都完整、以可讀的尺寸交出資訊嗎（整份菜單、每間房、每位講者、價格與包含什麼）？訪客離開時知道他來想知道的事嗎？主要動作是首屏上真的按鈕嗎？使用者還沒提供的內容是否以標明的 placeholder 呈現並列入回報？
13. **碰撞**：任何捲動位置有沒有東西壓在標題、陳述或按鈕上？有沒有元素跑出手機螢幕邊緣？手機上橫向捲動的列在截圖與多數訪客眼中都像被截斷，除非截斷明顯是刻意的。
14. **競品與可互動的東西**：把最近的競爭者名字放上去，概念還成立嗎？再說出那一個可互動的東西。任一個答案弱，就是這一輪的第一個問題，排在所有細節之前。

盲測紀錄：滿是模板裝置但豐富的頁面，每次都贏過乾淨但單薄的頁面。預設禁令拿掉裝置；第 11–13 道確保頁面沒有連實質一起拿掉。

## 3. 工作畫面：七個問題

儀表板、後台、設定、清單看完各寬度截圖後，書面回答（頁面的圖片、動效與可互動元素相關上限不適用於工作畫面）：

1. 畫面的問題是不是由畫面上最大的東西回答、而且最先被讀到？最大的數字是不是回答標題列那句話的那一個？
2. 每個區塊都共用畫面的邊緣嗎？有沒有一側的死帶、提早停住的卡、落單的格、被拉長而留下空白帶的卡（圖例被釘在卡底、四列資料的卡被拉到鄰居的高度）？
3. 顏色是否只在資料、狀態與唯一的主要動作上？主要資料元素是否帶著那一個色相？你選的那張「臉」在首屏看得到嗎？
4. 數字加得攏、而且逐位對齊嗎？列出每個出現兩次的事實並確認一致；用畫面上顯示的值重算每個總數與變化量；確認每個相對數字都寫了基準。
5. 每個零看起來都像零、每個缺值都像破折號嗎？每個計數徽章都在需要處理的佇列上、名詞從標籤看得懂嗎？
6. 每個圖例色票都和它說明的圖形一致嗎？有沒有圖說得解釋哪根是哪根（那就改成在圖裡編碼）？有沒有標籤和線或其他標籤碰撞？
7. 手機上導覽收起來了嗎？每個區塊仍回答它的問題嗎？

細節規則見 [app-screens.md](app-screens.md)。

## 4. 評分

像評審一樣打分（頁面適用；工作畫面可只答第 3 節）：四項各 1–10 分，權重 **設計 40%、可用性 30%、創意 20%、內容 10%**。

**設計（40%）**——構圖、字、色、圖、工藝。
- 9–10：每一屏都站得住像海報；沒有任何東西可以拿掉或移動。
- 8：有自信且連貫；一兩處設計師會注意到的弱點。
- 7：乾淨專業、系統清楚，張力少。
- 6：整齊但沒有身分，讀起來像套件。
- 5 以下：層級弱、間距隨意、預設字體、圖不搭。

**可用性（30%）**——三秒內定向、文字可讀、動作明顯、手機誠實。
- 9–10：不用捲就知道是什麼、給誰、做什麼；手機上無瑕。
- 8：清楚舒服；小摩擦（一段太長、一個目標太小）。
- 7：能用，有一個真問題（某處對比弱、手機版擁擠）。
- 6 以下：得用找的，或有東西壞了。

**創意（20%）**——一個能用一句話說出、並貫徹到底的概念。
- 9–10：只屬於這個主題、沒見過這樣用的概念。
- 8：清楚的概念加一個令人記得的動作。
- 7：已知作法的有品味執行。
- 6 以下：品類預設。

**內容（10%）**——具體、聽起來為真、經過編輯的文字與圖。
- 9–10：每一行都只可能是關於這個主題；圖像就是主題。
- 7–8：清楚具體，有些通用句。
- 6 以下：口號、填充、圖庫。

`總分 = 0.4×設計 + 0.3×可用性 + 0.2×創意 + 0.1×內容`

校準：真正的 Awwwards Sites of the Day 在評審手上約 7.5–8.0；誠實的 8.5 很少見。自己作品的第一個分數是 9，就換成「不是你做的那位評審」再打一次。

## 5. 上限（壓過算術）

- 任何寬度出現三行以上的標題、標題上方小標、等寬裝飾標籤、01／02／03 裝飾編號、裝飾性漸層、靜止元素上的陰影、裝飾性細線（未經品牌破例）：總分不超過 **6.5**。
- 第 3 道失敗（頁面可以屬於任何人）：創意不超過 **6**。
- 概念套在最近的競爭者身上也成立（第 14 道）：創意不超過 **7**。
- 沒有可互動的東西：創意不超過 **7.5**。
- 正式交付的頁面裡有灰框圖片 placeholder，或任何 lorem ipsum：內容不超過 **5**（使用者尚未提供、以標明 placeholder 呈現並列入回報的文字與資料不在此限）。
- 兩屏以上大部分是空底色，或內文又小又灰：設計不超過 **6.5**。
- 左右邊距不等、某段擠在一側而另一半空著、超過半屏的空白帶：設計不超過 **6.5**。
- 需求要的段落缺席或縮成幾個字：內容不超過 **6**。
- 首屏沒有主要動作的真按鈕：可用性不超過 **7**。
- 五秒測試失敗（首屏沒有說清楚這是什麼的標題）：可用性不超過 **6**。
- 有一段內文沒有命名它的標題：可用性不超過 **7**。
- 任何捲動位置有東西蓋住標題：可用性不超過 **6**。
- 揭示沒觸發留下空白帶，或內容被切出畫面：可用性不超過 **5**。
- 幾乎不動的頁面，或每塊同一個淡入：設計不超過 **7**。

## 6. 寫下評審

寫下來，不要只在腦中想；每輪用同一個格式，才能比較：

```
ROUND n
一秒看到：…
概念（一句）：…
可互動的東西：…
各段構圖詞：主視覺=… / …=… / …
分數：設計 _ · 可用性 _ · 創意 _ · 內容 _ → 總分 _._
套用的上限：…
前三個問題（最明顯的在前），各附出現的截圖與修法：
1. …
2. …
3. …
```

用設計師對同事說話的方式指出問題：「說明段落比標題左緣多出 40px」「推薦段是連續第三個分割版面」「手機主視覺把瓶子裁出畫面」。「可以更精緻」不是發現。

## 7. 先修什麼

依這個順序修；後面的救不了前面的：

1. **概念**：第 3 道失敗就換主視覺概念，不是修細節。
2. **層級**：每屏一個主角。先把大的變更大、小的變更少，再碰別的。
3. **構圖**：共用的邊緣、段落間距、段落間構圖的變化、破洞。
4. **字**：尺度對比、斷行、行長、行高。
5. **圖**：換掉弱的圖，統一裁切與調色。
6. **色**：比例與強調色紀律。
7. **細節**：狀態、focus、小對齊、手機微調。
8. **動效**：最後。

拿掉某樣東西留下缺口時，不要用另一種裝飾填回去：收攏缺口、放大剩下的，或讓圖或一片色域佔住空間。

## 8. 何時停

最多三輪：評審 → 修前三個 → 重新截圖 → 評審。某一輪找不到陌生人會注意到的問題，就提早停。第三輪仍低於 7.5，在回報中直說，列出剩下的問題；不要四捨五入往上報。
