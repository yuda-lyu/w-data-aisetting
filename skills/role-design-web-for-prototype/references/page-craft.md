# 頁面工法：盤點、論證、概念、文字、版面、圖像

**適用**：被「閱讀、捲動」的頁面——登陸頁、行銷／產品頁、作品集、活動、餐飲、單頁網站——以及 HTML 簡報的每一張投影片。被「使用」的工作畫面（儀表板、後台、設定、清單）改讀 [app-screens.md](app-screens.md)。

**數據出處**：文中的百分比與中位數出自 [taste-skill](https://github.com/Leonxlnx/taste-skill)（MIT）對 247 個策展網站（One Page Love、Awwwards Sites of the Day）與 2026-10 一批 Sites of the Day 的研究，以「研究」標示；標「推算」者是本檔依公式算出，不是研究數據。

## 1. 盤點主題

在筆記寫下 **8–12 件只屬於這個客戶、競爭者沒有的東西**。這張清單是第 3 節概念的來源，也是第 6 節找圖、畫圖的題材清單。可以從這些地方找：

| 面向 | 例子 |
|---|---|
| 名字與它的意思 | 店名的由來、人名、產品名拆開的字 |
| 地址與那個地方的樣子 | 門牌、街道、街區；那裡的磁磚、招牌、油漆顏色、店面字體、光線、天氣 |
| 需求裡的數字 | 座位數、房間數、到海邊幾分鐘、價格、創立年份 |
| 它必須遷就的限制 | 一個月只出一批、冬天休業、預約制 |
| 材料與顏色 | 木種、布料、釉色、產品本身的顏色 |
| 儀式與時間 | 清晨五點點爐、七點那班渡輪 |
| 它的世界裡的印刷品 | 時刻表、標籤、票券、菜單、收據、說明書 |

研究的盲測裡，每一題勝出的頁面都是從這種清單的某一項長出來的（客戶的名字與意思、它所在的街、讓它成為它的那個限制）；落敗的頁面構圖不差，但概念是整個品類共用的。

## 2. 寫論證

動手設計前，先在筆記回答五個問題，各一行：

1. 誰在讀？他們已經知道什麼？
2. 這是什麼——用做它的人跟朋友介紹時的說法？
3. 讀完一屏後，讀者該相信哪一件事？
4. 什麼能讓他們相信（這東西的照片、一個數字、一個名字、一段示範）？
5. 他們接下來要做什麼？

再把整頁列成「主張 → 證據」，一段一行：

```
1. 這是一張三腳橡木凳，接單製作。          → 凳子本身，放大
2. 每張座面取自同一塊板，所以木紋只屬於你。  → 三張特寫
3. 製作要六週，你可以跟著看進度。           → 各階段照片
4. 售價 240，由師傅親送。                  → 價格、按鈕
```

- **沒有主張的段落就是填充，刪掉。**
- **論證的順序就是頁面的順序。** 這樣才能逃出「主視覺 → logo 牆 → 三個功能 → 推薦 → 價格 → CTA」的罐頭順序。
- 頁面短沒有關係：研究中四分之一的網站只有一到兩屏。不要為了看起來完整而加段落。

## 3. 找概念

構圖手法說的是「怎麼排」，概念說的是「為什麼這一頁只屬於這個主題」。動工前把這一句寫進筆記，兩個空格都要從主題本身填：

> 在這一頁，**【屬於主題的東西】** 成為 **【構圖手法】**。

第一個空格去哪裡找：

- **它的產出**：它生產什麼？把真實的產出當成頁面的材料。
- **它的物件或形狀**：剖面、輪廓。放大、裁切，當成畫框或唯一的母題。
- **它的名字**：字母能不能裝進一張照片、疊成一面牆、拆到兩個角落？
- **它的地方**：有沒有一個景會讓人想去？
- **它的儀式**：有沒有一段順序可以隨捲動上演？
- **它的印刷品**：票券、菜單、標籤、收據、邀請卡、說明書。
- **它的反面**：哪個品類擁有它缺的那種感覺？

**競品測試**：把最近的真實競爭者（隔兩條街的麵包店、另一家橡木家具商）代進那一句。句子仍然成立，概念就屬於品類而不屬於客戶：「一條麵包」是每一家麵包店；「店名由來那條街上的七扇門」只屬於這一家。「乾淨、現代」不是概念。

**概念要走到最後一個像素**：價格、FAQ、頁尾都要問「概念在這裡做什麼」。頁面是菜單，價格就是菜單上的一行；名字是紀念碑，頁尾就是那個名字。研究中最常見的失敗——連高分網站也會——是第一屏很有特色，接著全是罐頭區塊。

**一個可互動的東西**：給頁面一件訪客能做、或每次來都不一樣的事，從概念長出來——選一種木頭看椅子變色、輸入名字看它用鑄字行的字型刻出來、設定貸款金額看真實的月付額。研究盲測中每一個勝出頁面都有一個，評審第一個提到的就是它。規則：用主題的真實內容；手機上用拇指操作得了；沒有 JavaScript 時有樸素的退路；不擋住閱讀；只有一個，不是遊樂場。它在實作階段就做進頁面，不是最後補一段動畫。

## 4. 寫文字

**先寫文字稿（純文字），再寫 markup。** 需要四行的標題，排版救不回來；滿頁口號，版面也救不回來。

### 4.1 標題：任何寬度都不超過兩行

標題是用來一眼看完的。研究中主視覺標題的中位數是 5 個英文字、32 個字元，70% 在桌機寬度是一到兩行。頁面上每個標題、在每個寬度，都要在兩行以內。

這是算術題，先算再愛上一句話：

```
每行字數 ≈ 行寬（px） ÷（字級（px） × k）

拉丁文：k ≈ 0.40 窄體；0.50 大多數無襯線與襯線體（顯示尺寸、緊字距）；0.58 寬體或全大寫
中文：  k ≈ 1.0（漢字字身是 1em 見方）
```

| 位置 | 行寬 | 字級 | 拉丁文兩行預算（研究，k≈0.5） | 中文兩行預算（推算，k=1） |
|---|---|---|---|---|
| 手機 390、左右各 20px | 350px | 44px | 約 32 字元 | 約 14 字 |
| 手機 390、左右各 20px | 350px | 34px | 約 42 字元 | 約 20 字 |
| 平板 768 | 690px | 64px | 約 44 字元 | 約 20 字 |
| 桌機，12 欄寬 | 1100px | 104px | 約 42 字元 | 約 20 字 |
| 桌機，半寬 | 620px | 72px | 約 34 字元 | 約 16 字 |

所以英文主標約 32 字元（四到六個字）、**中文主標約 14 字以內**，在每個寬度都能用有自信的字級撐住；手機字級降到 34px 左右時，英文可到約 42 字元、中文約 20 字。更長就是在寫一句話了，把其餘的移到說明句。

控制斷行：

- 標題給 `max-width`（拉丁文用 `ch`、中文用 `em`）讓它在你要的地方斷，再加 `text-wrap: balance` 讓兩行等長。
- 斷點重要時（通常都重要）自己寫：`給小廚房的<br>凳子`。看手機截圖；手寫的斷行在手機上又折行，就在斷點下把 `<br>` 藏起來，或刪字。
- **絕不只靠縮小字級**解決長標題。9 個字縮到 28px，比 5 個字放在 64px 更糟。
- 第二行不要只剩一個字（中文也一樣，不要只剩一兩個字）。刪字重新平衡，不要微調寬度。

段落標題遵守同一規則，而且更短。

**陳述不是標題。** 主視覺後的宣言句、放大的引言，是段落：用 `<p>` 或 `<blockquote>`，字級在陳述尺寸（桌機 36px 以下、平板 32px、手機 24px），可以到約三行（手機四行）。設得更大、標成 heading、或當成首屏主句，它就是標題，受兩行規則限制。盲測中，大字設成三行以上的句子一律被當成長標題。

### 4.2 標題的形狀

挑最樸素且為真的一種：

- **名字**：品牌或人名，設得非常大，另一處用一行說明。名字短、主題有畫面時最強（工作室、餐廳、旅館、人）。
- **它是什麼**：「口袋裡的唱片架。」「給小房間的家具。」品類，加一個具體的字。
- **主張**：競爭者簽不下去的一句話。
- **指令**：動詞開頭，短。
- **地方或時刻**：「南極。」「里斯本，1984 年起。」適合旅宿、活動、旅遊。

要避開的形狀（它們是所有登陸頁的平均值）：

- 填空式：「為現代團隊打造的 AI 驅動平台」。
- 三連句：「快速。簡單。安全。」
- 糾正式：「它不只是工具，而是工作流」「不只是……」。
- 「X，重新定義」「歡迎來到……」「認識……」（介紹沒人見過的產品）。
- 讀者沒問的問句。
- 需要冒號的標題：「XX：給自由工作者的發票工具」——名字已經在導覽列。
- 標題裡一個字換樣式（斜體、襯線、上色、底線、包膠囊）。

### 4.3 說明句、內文、按鈕、導覽

- **說明句**：一句，具體說這是什麼、給誰。從標題刪下的細節放這裡；不要換句話重說一次標題。放在標題正下方 32–48px，與標題同時出現——不要沉到首屏底部，也不要被動畫晚放出來。標題是名字或比喻時，這一句要直白說明它是什麼。
- **首屏回答訪客的第一個問題，用大字**：活動——是什麼、何時、何地（日期要在標題或第二級字級，不能只在小字）；產品——是什麼、多少錢或能做什麼；個人——是誰、做什麼。訪客為之而來的每一段（陣容、菜單、房型、價格）都有自己的標題與導覽位置。
- **內文**：短段落、平實陳述。用具體名詞與真實數字：「一週內出貨」勝過「快速到貨」，「38 個座位」勝過「溫馨」。每一句都問：換一家公司能不能原封不動印出來？能，就磨利它或刪掉。使用者給了的內容要完整呈現，不要縮成幾句——研究盲測中，內容單薄是乾淨頁面輸給繁複頁面最常見的原因；使用者沒給的，依主檔「缺資料」規則處理。
- **按鈕**：以動作或對象命名（「預約座位」「查看方案」「下載 Mac 版」），簡短。主要動作全頁同一個名字。每屏一個主要按鈕，次要動作用文字連結。不要每個連結和按鈕都帶箭頭；要用，最多只放在主要動作上。
- **導覽**：字標、最多五個單一名詞的連結、一個動作。

### 4.4 證明：不編造

絕不編造客戶、具名引言、媒體 logo、使用者人數、評分或效能數據——編造的證明既不誠實，也是公認的 AI 味。使用者沒有提供證明時，用「本來就成立」的東西：

- 把東西本身放大給人看。真實的示範勝過任何引言。
- 具體說明它怎麼運作。
- 用需求裡的事實（價格、地點、年份、材料、包含什麼）。

### 4.5 一眼就是生成的文字

- **該類型的動詞與形容詞**：英文的 unlock、unleash、supercharge、elevate、empower、streamline、seamless、effortless、robust、cutting-edge、next-generation、world-class、all-in-one、blazing fast；中文類推（非研究數據）：「賦能」「無縫」「一站式」「顛覆」「極致」「重新定義」「全方位」「助力」。
- **假裝成編輯風的標籤**：「Field notes」「The details」「Our philosophy」「Quietly trusted by」。段落標題直接寫「價格」就好。
- **家具文字**：時區或時間條、「Est. 2024」、座標、版本戳記、「Scroll」「（往下捲動探索）」、假的攝影署名、「Available for work」加一個圓點、用中點或斜線串起來的字串。
- **破折號成了習慣**：一頁一兩個是寫作，十個就是模型。英文用句號；中文的「——」同理，別每句都用。
- **旁白式說明**：「一個乾淨、簡約的版面，用來……」。
- **重複數字的步驟標籤**：「Step 1」「Phase 02」。
- **處處三個一組**：三個功能、三個數字、三個步驟。內容有幾個就用幾個。

### 4.6 微排印

- 中文用全形標點與「」『』；拉丁文用彎引號（“ ” ’）、真正的刪節號（…）、範圍用 en dash（9–5）。
- 數字與單位之間不斷行（`&nbsp;` 或 `white-space: nowrap`）；標題最後一個短字會落單時同理。
- 價格、表格等需要對齊的數字用 `font-variant-numeric: tabular-nums`。
- 標題 `text-wrap: balance`，段落 `text-wrap: pretty`。
- 超過三個字的英文不要全大寫；要用大寫，加 0.02–0.06em 字距。
- 沒有小於 13px 的文字。置中的段落不超過三行。

## 5. 版面

### 5.1 強頁面在做什麼（研究，114 個 7.3 分以上的網站）

- **邊距窄，內容貼到邊。** 約 45 個用 32px 以下的外邊距，只有約 8 個用 80px 以上。置中的 1100–1300px 容器在強網站是少數，卻是被評為「罐頭」那些網站的常見框架。
- **文字掛在偏離中心的一條線上**（約 22 個）：三分之一處、42%、中線。
- **兩到三種字級，中間沒有**（約 30 個）。
- **一屏一件事**（約 20 個）。
- **段落靠底色區分**：約 20 個每段換整片底色，約 12 個深淺交替，約 10 個從不換色、只靠空間分隔。
- **段落重新構圖，不重複**；**刻意打破系統一次**（約 14 個）。
- **字很少**：全研究中位數 575 個英文字，有些最好的不到 200。

### 5.2 邊距與格線

```css
:root {
  --margin: clamp(1rem, 2.2vw, 2rem);   /* 16–32px：窄，內容貼到邊 */
  --gutter: clamp(0.75rem, 1.4vw, 1.5rem);
}
.wrap { padding-inline: var(--margin); }
.grid { display: grid; grid-template-columns: repeat(12, minmax(0, 1fr)); column-gap: var(--gutter); }
```

- 全頁一組邊距、一套格線；每條左緣都是一條欄線。
- 不要反射性地把整頁包進 `max-width: 1200px; margin: auto`。讓大的東西（字、圖、色域）跑滿寬，只限制內文的行長（`max-width` 用 `ch`／`em` 下在段落上，不是下在頁面上）。
- 超寬螢幕把版面上限設在約 1760–1920px，或讓 `vw` 字級用 `clamp()` 停止成長。
- **不要畫出格線。** 欄線、十字準線、輔助線都是裝飾；格線靠對齊被感覺到。

### 5.3 文字放在哪

- **挑一條錨線並重複使用**：主標從第 5 欄開始，段落標題、價格數字、頁尾連結也從那裡開始。全頁兩到三條錨線；六條代表什麼都沒決定。
- **偏離中心勝過置中**：標題在左三分之一、段落在最右欄、同一基線、中間什麼都沒有；標題在下三分之一、上方是刻意的空白；文字停靠在角落、中間交給圖。
- **兩端**：同一條基線兩端各一段短文字（左邊名字、右邊一句說明），是置中堆疊最常見的替代。
- **置中是一個決定**：強頁面置中時，是一條軸、兩側寬闊留白、一屏一個元素，不是「標題＋段落＋兩顆按鈕」的置中堆疊。
- **長文用列**：標題在左三分之一、內文在右三分之二，全頁每一列用同一種切法。

### 5.4 空白：留白與破洞

空白是被放置的，不是剩下的。讀者把每一塊大空白判為兩種：**留白**（有東西把它收住）或**破洞**（沒有東西收住）。強網站有很多留白，但約一半仍留著至少一個破洞，而破洞就是訪客會說出口的（「莫名其妙的大片空白」）。

**誰能收住一塊空白**：圖片本身（天空、地面、物件）且文字停靠在它的邊；空白帶對側的一張圖；大到撐滿空間的標題，或同一基線兩端的兩段短文字；單屏頁面四角的字標、導覽與一則事實。

**破洞從哪來**（依頻率）：段落間距拉太開（250–760px 的空底色）；一段的文字在一半、另一半空著；內容晚到（揭示動畫還沒觸發，訪客捲到空地）；短區塊被撐成整屏；釘住的場景好幾屏幾乎沒東西；高低不一的圖頂端對齊，短圖下方空一塊。

規則：

- 決定空白在哪、說出誰收住它；沒人收住就是破洞——把該段的圖移進去、放大主角，或把空間拿掉。
- 段落間距：桌機 120–240px（研究中位數約 230–250px），手機 72–112px；換底色時可以稍小。兩段之間的空底色超過一屏的約 40% 就是破洞。
- 段落之間的距離明顯大於段落內任何距離；標題上方空間至少是下方的兩倍。
- 頁面上沒有任何一段超過約半屏高的地方是什麼都沒有的。
- **內容在第一次繪製就就位**。進場動畫移動的是已經在那裡的東西，絕不讓訪客看著一屏空地等字飄進來。
- 區塊高度跟著內容；`min-height: 100vh` 屬於真的填滿一屏的段落，不屬於頁尾或孤零零的標題。
- 一排高低不一的圖：底部對齊、在短圖下放東西，或統一裁成同一比例。
- 留白是一屏一件事（一行字、一個物件、一張圖或一片色域），**全頁最多一次**。一屏什麼都沒有永遠不是留白。
- 某段看起來空時，答案幾乎從來不是「加東西」：放大主角，或刪掉這段。

### 5.5 版框：邊距、平衡、標題

讀者在看任何細節前先判斷版框：「沒有好的邊距」「全部擠到一邊」「沒有清楚的標題」。

- **左右外邊距相等，每個寬度都是。** 研究中強網站的左右邊距相差只有幾個像素；沒有一個強頁面是被推到一邊的。邊距 16–32px，任何寬度（含手機）都不小於 16px。導覽列與內容用同一組邊距（最常見的小毛病是頁首一個內縮、內容另一個）。
- **出血是刻意的，且從邊距起算**：一排跑出右緣的圖從左邊距開始；出血不移動邊距。不對稱放在版框內（偏心的錨線），不放在版框本身。
- **用滿頁面給的寬度**：研究中約百分之一的文字段落讓一半寬度空著。文字佔一邊時，另一邊放這段的圖、第二欄、清單或大數字，絕不留空底色。中間也算：卡片在左緣、孤單的按鈕在右緣、中間三分之一空著，一樣是破洞。首屏也算：句子和按鈕佔左三分之一時，右上要有東西（圖、影片、一則事實、動作）。
- **讓一行字剛好撐滿寬度**要靠量測（用小腳本依容器寬設字級，或 SVG text 的 `textLength`），不要猜一個字級——差幾個像素跑出邊緣看起來就是錯。
- **首屏一個 `h1`，說清楚這是什麼**：顯示尺寸（桌機 32px 以上）、最多兩行；名字＋做什麼、產品＋用途、活動＋日期地點。`h1` 是名字時，下面那行（18px 以上）說它是什麼。它在第一次繪製就在，不被載入畫面擋住。
- **每段都有標題**：研究中 82% 的文字段落以標題開頭（中位數 57px，約內文的三倍半），從外邊距或頁面的錨線開始，每段同一位置。沒有標題時常見的替身是小標籤（大寫、等寬、括號編號）——在本技能都是預設禁令；把標籤的字寫成段落尺寸的標題（「房型」「怎麼運作」「價格」）。

### 5.6 段落：帶著概念、換著排

- **相鄰兩段不用同一種構圖。** 給每段一個詞（分割、清單、陳述、滿版、拼貼、表格、條帶、釘住……）；同一個詞連用兩次、或全頁出現三次，就是模板在露臉。
- 密與疏、圖與字、亮與暗交替，讓捲動有節奏。
- **重複的模組只用在檔案庫**（作品索引、菜單、時刻表）；其他地方的重複讀起來像套件。
- **打破系統一次**：系統建立後，一個計畫好的例外（一行置中、一段反白、一張不同尺度的圖）讓規則被看見。

### 5.7 導覽

- 樸素的形式：一端字標、三到五個文字連結、一個動作，全用內文字級，放在頁面底色上，沒有橫條、框線或背景。研究中位數是 3 個連結；也常見更少（角落的小連結、只有一個動作）。
- 固定在頂部時，**絕不能蓋到內容**——每個捲動位置都要在截圖檢查，手機尤其。浮動膠囊列是最常蓋到文字的。
- 手機：字標與一個動作在畫面內；連結收進以文字按鈕（「選單」）開啟的全螢幕面板，只有三個時移到頁尾。導覽在桌機不超過首屏約十分之一高，手機是一列。盲測中吃掉主視覺的導覽列讓可用性掉了整整一分。

### 5.8 結尾

頁面以一個設計過的場景結尾，不是網站地圖：全寬的名字、反色重現的主視覺、一則聯絡事實當標題，或安靜的一行。實用資訊（地址、營業時間、email、法律聲明）用內文字體、可讀尺寸、放在同一組錨線上。

### 5.9 手機是第二個構圖

把 390px 當成一頁自己的設計，不是桌機擠小。

- 首屏仍是一件清楚的事。桌機 20vw 的字標，在手機疊成兩行、26vw，可能更強。
- 重寫斷行；把圖重裁成直式（各斷點不同的 `object-position`）；用交錯的寬度保留參差，不要全部變全寬。
- 邊距 16–20px；內文 16–18px；觸控目標約 44px 高（需做無障礙時 44×44 為合規門檻，見主檔〈受眾分級〉）。
- 每一輪都看 390px 的截圖：橫向捲動與三行標題通常最先在這裡出現。橫向捲動的列在截圖與多數訪客眼中都像被截斷，除非截斷明顯是刻意的，否則換行。

### 5.10 頁面怎麼失敗（研究，54 個 6.8 分以下的網站）

整頁是品類的罐頭模板、換個 logo 就是任何競爭者（約 20）；置中標題＋膠囊徽章＋兩顆按鈕＋下方截圖或磚格（約 9）；有特色的主視覺接著罐頭模組（約 8，中段分數還有約 17）；沒有個性的預設字體（約 13）；文字太小或對比太低（約 13）；頁面從頭到尾沒說這是什麼，或沒展示作品（約 12、7）；單薄內容拉成很多屏（約 11）；內容前的門檻、載入畫面、彈窗（約 9）；手機版是桌機縮小或壞掉（約 8）；固定元素蓋到內容（約 7）。

## 6. 圖像

研究：60% 的網站有一張媒體佔首屏一半以上（高分網站 68%）；高分頁面的圖量中位數 37 張，低分頁面 5 張——強網站展示，弱網站描述；73% 的網站媒體是直角。

### 6.1 正式交付的圖從哪來（依優先序）

1. **使用者自己的圖**：產品照、地方、人、作品。平凡的真實照片勝過別人的漂亮照片。先問有什麼、再到專案裡找。
2. **能生成的圖**（本次工作階段有影像生成工具時）：提示詞寫成攝影 brief——主體、角度、光線、背景、裁切比例，並註明「不含文字」。先生成主視覺，其餘配合它的光線。
3. **以程式碼繪製主題自己的東西**（6.4 節），用在沒有真實圖可用的地方。
4. **純字與色**（6.5 節），當成刻意的設計。

v0 草稿可以用標明長寬比的 placeholder；**正式交付不留灰框**。不要拿與主題無關的圖庫照片冒充主題本身（霧中公路放在餐廳頁，評審一眼就認出是圖庫）。

### 6.2 裁切與擺放

- **選少數幾種比例並守住**：例如人像 4:5、風景 16:10、細節 1:1。比例亂跳像圖庫傾倒。
- **放大**：全寬，或半屏寬全屏高，才有存在感；六張小圖排成格子沒有存在感。圖好就給空間，不好就刪。
- **有意識地裁**：`object-fit: cover` 搭配每張圖各自的 `object-position`，讓主體落在構圖需要的位置。
- **讓圖碰到邊**：滿版或一邊出血讀起來是設計過的；四邊等距浮著的圖讀起來是預設擺放。
- **重疊要少且刻意**：每屏最多一處（標題最後一行壓過圖上緣、小圖壓大圖固定 40–80px）。
- **直角**，除非方向或母題另有規定；要圓角就全頁同一個半徑。
- **不加框**：頁面上的圖不加邊框、不加陰影、不套筆電或手機外框。
- **圖說**：一行短句、小字級、柔和墨色，靠圖左緣對齊；多數圖不需要。

### 6.3 處理：全頁一種

- **不處理**（預設）：挑光線本來就一致的圖。
- **灰階**：`filter: grayscale(1) contrast(1.05)`，套全部或都不套。
- **在色域上正片疊底**：淺色平塗底上用 `mix-blend-mode: multiply`，讓棚拍白底消失、產品直接坐在顏色上。
- **為深色頁壓暗**：`filter: brightness(0.85) contrast(1.05)`。

不算處理的：照片上蓋色、雙色調疊層、模糊、顆粒疊層、暗角、歪斜加陰影的拍立得框。

照片上的文字只在照片有安靜區域時才放；沒有就把文字移出圖外。需要時加只覆蓋文字區的中性遮罩：40–55% 黑的實色塊，或下三分之一由 55% 黑漸變到透明——這是預設禁令裡唯一允許的漸層。絕不用彩色遮罩。

### 6.4 呈現軟體

- 用 HTML 照真實尺寸做出介面的一個**片段**，裁到能說明重點的部分（一個控制項、一列、一個面板），不要用縮小的截圖或裝飾性 mock-up。
- 片段裡的文字與數字用使用者提供的真實內容；缺的依主檔「缺資料」規則處理。**灰條代替文字比沒有圖更糟。**
- 片段直接放在頁面上或一塊平塗的底色上；不套筆電、手機外框（除非產品本身是手機 App，且外框是素面圓角矩形）。
- 片段內部遵守產品自己的介面慣例（小圓角、1px 控制項邊框、開啟選單的陰影），在片段根元素加 `data-ui` 屬性標記，頁面的預設禁令不管片段內部，片段 CSS 寫在 `[data-ui]` 選擇器下。`data-ui` 只給裁出來的片段，不可包住整段或標題。片段內部規則見 [app-screens.md](app-screens.md)。
- 使用者給了真實截圖時，至少放一次大而不裁的。

### 6.5 以程式碼繪製主題

沒有真實圖可用時就畫，而且要畫好。inline SVG 與 CSS 就夠。

- **畫主題自己的東西**，不是裝飾：凳子的三隻腳和座面木紋、麵包店門上的琺瑯招牌、小屋的兩扇窗和煙囪、街道圖、工具產出的那張發票、音樂祭的舞台。說不出畫的是主題世界裡的什麼，它就是裝飾。
- **全頁一種圖像語言**：平塗形狀，不描邊或統一一種線寬；全頁同一套轉角與曲線語彙；用配色裡真正的顏色（色域與強調色全強度，不是灰色）。一組看得出是一家的圖讀起來是識別；風格混雜讀起來是剪貼圖庫。
- **顏色就是材料**：以表面質感為賣點的產品，用那種質感的顏色畫；海邊小屋用海的藍與沙色；絕不是一頁灰色 placeholder。
- **三層細節**：一眼可讀的大形狀、描述物件的中形狀（把手、窗框、台階）、值得再看一眼的小細節（製作者標記、門牌、缺角的磁磚、鉸鏈、屋頂上的鳥）。用平塗的色階做出光影（一個受光面、一個陰影面），不用漸層。放大到全尺寸後會被當成 placeholder icon 的圖，還沒畫完。評審把簡單的圖一律評為「陽春」。
- **畫大，讓它工作**：當主視覺的主角、一條全寬帶、一組磚、頁尾標記。散落的小塗鴉讀起來是填充。
- **讓它把概念帶過整頁**：同一個畫出來的物件以不同尺度回來；磁磚格變成營業時間；地圖變成預約區。
- **誠實**：若訪客可能把畫當成真實產品，在第一張畫附近或頁尾用小字說明「在照片完成前以繪圖呈現」；交付回報列出哪些圖是照片的代替品。
- **不是這些**：漸層打光的 3D 色塊、等角剪貼圖、坐在筆電前的通用線條人物、漂浮的抽象形狀、方塊裡的 icon。

### 6.6 純字與色

這是正當的設計，不是要掩飾的缺口；研究中完全沒有圖像的少數網站，評分中位數 7.5，高於整體的 7.2。

- 讓字成為圖：一句 10–14vw 的陳述、5vw 的清單、顯示尺寸的數字。
- 大面積用色：整片色域、一段反白、兩片色域對切。
- 方向需要時，用主題自己的形狀當一個平塗母題（圓、弧、缺口），用 CSS 畫、被視窗裁切。
- 不要加：方塊裡的 icon、抽象漸層、點陣、波浪分隔線、漂浮形狀、emoji、通用線條插畫、「圖片將放這裡」的空框。
