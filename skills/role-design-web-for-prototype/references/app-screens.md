# 工作畫面工法：儀表板、後台、分析、設定、清單

**適用**：被「使用」而不是被「閱讀」的畫面——儀表板與總覽、後台與管理、分析與報表、設定與帳務、要逐筆處理的清單（收件匣、佇列、帶篩選的表格）、錢包與財務首頁、編輯器與建構器、單一物件的詳情頁。互動原型裡的 App 介面、頁面上展示的產品介面片段（根元素標 `data-ui`），內部也照本檔。被閱讀的頁面改讀 [page-craft.md](page-craft.md)；同一個需求兩種都有時，各照各的流程，共用一套配色與字體。

**數據出處**：數字出自 [taste-skill](https://github.com/Leonxlnx/taste-skill)（MIT）對 23 個真實產品畫面（17 個產品、17 亮 6 暗、皆為 1440 或 1512px 桌機寬度）的量測與中位數，以「研究」標示；研究沒有涵蓋的（手機、載入與錯誤狀態等）標「規則」，是 taste-skill 依盲測評審訂下的作法。

## 1. 生成的儀表板 vs. 真的產品畫面

生成的儀表板是所有儀表板模板的平均值：深色或帶色的側欄、選中項目一顆彩色膠囊、「歡迎回來 👋」、四張 KPI 卡各配一個淡色圓圈 icon、綠色的「+12.5%」和一條迷你走勢線、漸層面積圖、上面是大寫表頭的斑馬紋表格。沒有一處是錯的，也沒有一處是決定過的。

研究中真的產品畫面與生成畫面的差別，依明顯程度：

1. **顏色放在資料上，不放在外殼上。** 中位數畫面只有約 3% 的像素帶色；23 個中有 12 個完全沒有實心的主要按鈕。
2. **KPI 是字，不是磚。** 沒有一個畫面在 KPI 上放彩色圓圈 icon，也沒有一個放迷你走勢線。
3. **表面是平的。** 23 個中 17 個卡片沒有陰影；分隔用 1px 線或一階色差。
4. **沒有主視覺式的大標題。** 9 個畫面沒有任何大於 16px 的標題；有標題的中位數 24px。
5. **圖表幾乎沒有外框裝飾。** 單一序列沒有圖例；格線 3–7 條淡線或沒有。
6. **導覽往後退。** 選中項目是中性灰膠囊或文字變色；彩色左側條只出現一次。
7. **表格靠線與對齊。** 沒有斑馬紋、沒有表頭色帶，數字靠右。
8. **資料狀態誠實。** 零就印零、缺值是灰色破折號、空區塊保留外框。

拿掉模板的裝置只是一半；另一半是實質：產品真實的資料、先回答畫面那個問題的版面、算得攏的格線。盲測裡，只做了「乾淨、安靜、正確」的畫面輸給了更豐富的畫面，評審每次的理由都一樣，各自成為下面的一條規則：首屏太單薄（§2.3）、看不出是哪個產品（§3）、克制到藏起了意義——延遲上升和流量上升是同一種灰（§5）、沒有可以做的事（§2.3）、同列卡片底部參差（§4）。

**給產品一張臉**：評審最常見的抱怨是「套件套得很好，但不是一個有自己身分的產品」（預設字體、#f8f8f8 底、白色 12px 圓角卡片）。在動工前就決定、並確認第一張截圖看得到：

- **一個從需求取來的面貌**：從產品的世界取色的底、有個性的數字字體、品牌色放在主要資料元素上——三選一，寫進筆記。
- **產品的標記與名字**在外殼頂端，為這個產品畫（從名字或它的物件取一個簡單的字母組合或符號，用強調色），不是黑方塊裡一個字母。
- **一個只有這個產品才有的元素**，用它自己的東西做：能源住宅的電力流向、麵包店的售罄時間條、請假系統的人力覆蓋對照最低人數、跑團的配速分組。寫進筆記，放在畫面那個問題旁邊。
- **圖表那一個色相放在主要資料元素上**：今天那條線、已預訂的長條、本期、超支的那段。整個畫面唯一的色相只出現在變化量上，讀起來就是套件。
- **人與物件以本來的樣子出現**：每個人一個穩定的首字母與自己色相的淡色，相鄰列出的人色相相差至少 60 度；這些淡色是身分不是資料，保持淡、不進圖例。產品顯示縮圖，封面藝術顯示封面。
- **行話**：標籤與空狀態用這一行的詞（「等客戶回覆」「病假」「28 號到期」），不用模板的泛稱（「項目」「紀錄」「狀態」）。

## 2. 流程

### 2.1 盤點資料與任務

在筆記寫 8–12 行：

- **物件**：畫面顯示的東西（部署、發票、成員、活動、對話）與它們的欄位、單位。
- **真實量級**：有多少個、典型金額、比率的範圍、數值在一天／一月／一年如何變動；新帳戶時它們真的有多小。
- **人**：誰打開這個畫面、多常（每天看一眼，或一坐八小時）、用什麼裝置。
- **任務**：他們接下來從這裡做什麼（核准、回覆、付款、出貨、邀請），哪個最常發生。
- **產品自己的東西**：名稱與標記、畫面所屬的工作區或帳戶、裡面的人（兩位合夥人、六人團隊、俱樂部成員）、人們一眼認得的物件（商店的商品照、媒體工具的封面、路線地圖）。規劃每一樣出現在哪裡。

**資料**：畫面上的數字依主檔「缺資料」規則取得（向使用者索取；未取得前以標明的 placeholder 呈現，不寫 Lorem、Acme、John Doe、「使用者 1」這類看似真實的假名）。拿到的資料放在一個 JSON 或 JS 檔，畫面從它渲染：

- **總數由明細算出**，不另外手打。
- **必須一致的數字寫成斷言**（`console.assert(sold - cancelled === rsvps)`、各區間加總等於總數），並看 console。盲測中，一張票券表和自己的 KPI 對不攏，評審就不再信任整個畫面。
- **同一個事實出現兩次就是同一個變數**：KPI 標籤、圖上的陰影區間、側卡都提到的時段，在資料檔裡只有一個值，文案與圖表註記都從它組出來。兩張卡差半小時，比少一張卡更傷信任。
- **總數與變化量由畫面上「顯示的」部分算**：加總畫面顯示的四捨五入後金額，不要另外把未四捨五入的總數再四捨五入；變化量是畫面上兩個值的差。
- **每個相對數字在同一句話裡寫出基準**：「比收店早 3 小時 40 分」「比上週日早 45 分」「比平常週一多 5」。只寫「提早」「上升」「+5」，會被讀成相對於旁邊那個數字。
- **同一個時刻只用一個名字**；錯誤狀態要改寫狀態列。
- **要靠圖說解釋哪根長條是哪個時，改成在圖裡編碼**：標出的時段用第二色調並有自己的圖例、帶正負號的軸、直接標在圖形上的標籤。

### 2.2 這個畫面的一個問題、一個發現

每個畫面先回答一個問題：「今天的營收進來了嗎？」「哪一次部署壞了？」「誰在等回覆？」「這個月的方案還剩多少？」寫成一行。它決定三件事：

- **什麼最大**：最大的區塊永遠是承載這個問題的那一塊（圖、方案、環、清單）；最大的數字回答標題列那一句回答的問題。
- **什麼先讀**。
- **什麼不放**：只有幾個數字時不畫圖（研究中 4 個畫面不畫圖；設定頁用三個用量數字並連到分析頁）。

再寫下**一個發現**：今天的資料裡最需要注意的事實（「8 人候補時有 9 人未到」「23:28 的部署讓錯誤率翻倍」「外食超支 36 元」）。放在第一眼會讀到的地方——標題下那一行，或主要數字的副標——並緊鄰它帶動的動作。盲測中，重要的發現縮在卡片底部 14px 的說明裡，整個畫面讀起來很平。

然後把畫面的區塊列成「下一個問題的答案」，一行一個；沒有問題的區塊刪掉。這樣才能避開「KPI 列 → 大圖 → 兩張小圖 → 表格」的罐頭順序。同類產品若有知名的畫面編排，不要照抄——評審一眼就認出；結構從產品自己的東西取（例如一對伴侶的預算用「兩人＋共同」三欄貫穿帳戶、計畫與帳單）。

### 2.3 首屏與動作

- **需求點名的每一塊都在首屏**：1440×900 下，每個區塊至少露出表頭和前幾列或它的數字。主區塊高度依問題定（約 200–360px）；長清單限 4–6 列並附「查看全部」；有時效的區塊（即將到期的帳單、快到期的 SLA、失敗的部署）放在長表格之前。一條大部分時間是平的線，不給滿寬：給三分之二，旁邊放下一個答案。
- **最常做的任務一鍵可達**：寫出它（「打包今天到期的訂單」「回覆最久未回的那筆」「重新部署失敗的版本」），控制項放在答案出現的地方——標題列的主要按鈕、需要它的那一列上的動作、失敗項目上的「查看紀錄」。沒有主要任務控制項的畫面讀起來是報表，不是工具。
- **證據放在答案旁邊**：「錯誤率 0.28%」附上它的尖峰註記（「23:28 部署後一度到 3.9%，已回復」），比單一數字更可信。關鍵事件旁一行解釋，勝過再一張圖。

## 3. 外殼

- **五種原型**（研究）：開放平面（帶標籤的側欄直接在頁面底色上，無頂列）；帶色框＋白紙（側欄與頂列共用淡色底、頁面是內縮 8px 的白色紙面）；線分 T 框（210–240px 側欄＋64px 頂列，只用 1px 線分隔）；icon 軌（50–60px、無標籤，省約 180px 寬）；無側欄（46–48px 頂列＋置中欄）。
- **亮色畫面上絕不放深色或飽和色側欄**（17 個亮色畫面 0 個）；深色畫面全部是同一片底，用 1px 線或什麼都不用分隔。
- **側欄**：寬 224–240px（中位數 230）；列高 32px、間距 34px 最常見；icon 14–20px（中位數 16）、約 1.5px 描邊的線框；標籤 14px、400 字重。**選中項目**：亮色畫面用中性灰膠囊、標籤不變；暗色畫面只靠亮度（標籤由 #bbb 變 #fff）。群組標籤用 12–13px 灰色一般大小寫，不用全大寫。
- **產品有名字**：產品標記與名稱在側欄或軌頂端，範圍（工作區、團隊、專案、帳戶）以切換器或麵包屑呈現。截圖裡叫不出產品名字的畫面讀起來是模板。
- **導覽上的計數**只放在需要處理的佇列，且名詞清楚（「申請 5」）。
- **預設有標籤**；只有目的地五個以內且畫面需要寬度時才用 icon 軌，此時每個 icon 都有 tooltip（需做無障礙時另加無障礙名稱，見主檔〈受眾分級〉）。導覽項目是其他畫面，不是本頁錨點。
- **頂列預設不放**；要放就必須承載真的東西：搜尋、工作區切換器、頁面或物件名。一條大半空白的頂列是缺陷。
- **浮動按鈕**：只有當它是畫面唯一的主要動作、且任何寬度都不蓋到內容時才用。

**標題**：

- 每個畫面一個 `h1`，18–32px（研究中位數與眾數 24px），600–700 字重；或由麵包屑最後一項當 `h1`（16px）。
- **名詞，不是問候**：「分析」「總覽」、專案或物件的名字。問候只適合個人或團隊首頁，且不帶 emoji。
- 可選的第二行：一句 14–16px 灰色，關於資料或物件（發現、期間、範圍），不是關於介面（「此頁顯示……」讀起來是說明書）。
- 標題右側只放真的動作；沒有就什麼都不放；或放資料更新時間戳記附重新整理按鈕。
- 主要按鈕每畫面一個，通常近黑色；研究中 12 個畫面沒有實心主要按鈕。

**分頁籤、篩選、日期範圍**：日期範圍放頁面層級或各卡片，不兩者都放；底線分頁籤坐在一條全寬 1px 線上，指示條 1–4px；分段控制項寬度跟選項一樣，約 480px 以下才全寬；標題列與篩選列控制項高度 28–40px（中位數 34）；順序是範圍在左（日期在先、再篩選）、工具與重新整理在右。

## 4. 版面算術

- **寬度**：流體（側邊距 17–64px，中位數 29）或置中（資料頁約 1100–1250px）。標題距畫布頂 20–88px（工具類 20–36）。**一個 gutter 值**，水平垂直都用它（混用 12 與 16、20 與 24 在研究中被標記 8 次）。
- **一條左緣、一條右緣**：最強的畫面從頁首到最後一列只有一條左緣；寫下你的加總算式並確認它閉合（例：3×372 + 2×17 = 2×568 + 16 = 1152）。
- **格線不配資料造成的死空間**是研究中最常見的失敗（10 個畫面）：四張 KPI 放三欄、第四張落單；一張卡獨佔三欄的一列、旁邊 810px 空著；卡片被拉到鄰居的高度、圖例下面 250px 空白。**欄數由項目數決定**，落單的卡跨欄，不要把卡框拉過空白。
- **同一列的卡片共用底緣**：先用內容平衡（調清單列數、兩邊限同樣筆數、配對高度相近的區塊）；平衡不了才堆疊，或讓短卡內容靠上、把「查看全部」或總計釘在卡底，讓多出的高度不是破洞。被拉長的卡只能把動作或總計釘在底部，圖例與註記要緊貼圖下。
- **窄區塊不橫跨畫布**：五欄以內的表格、六列以內的清單，在 1440 寬約 760px 並與下一個區塊並排；拉到 1300px 會在名字與第一個數字之間留下 400–600px 空洞。

## 5. KPI 與變化量

- **不自成一磚**：預設是一個容器以 1px 分隔線切成等寬欄；常常更好的是不設 KPI 列，把每個主要數字放進解釋它的那張卡。
- **數量** 1–6 個一列（中位數 3–4），欄數等於個數。
- **尺寸**：數值 16–40px（中位數 26，眾數 24），沒有 48px 以上的；標籤 12–16px（中位數 14），數值約為標籤 1.7 倍。標籤在數值上方、灰色、一般大小寫。
- **其他什麼都不加**：不放彩色圓圈 icon、不放迷你走勢線、不放淡色磚。標籤旁一個資訊 icon 可以。單位是較小的灰色後綴（「5 分鐘」24px 配 14px）。
- **答案數字領頭**：畫面的答案是某個數字（餘額、淨值）時，它 30–36px、至少是兄弟數字（18–24px）的 1.3 倍，畫面上沒有更大的數字。
- **一個數字一個位置**：KPI 列已有的數字不在旁邊圖例重複。
- **變化量**（研究 20 個有 KPI 的畫面中 9 個有）：10–15px、不大於標籤；**用文字寫出比較窗口**（「與前 30 天比」）；只把數字上色，或整個變化量用灰色。
- **顏色表示好壞，不表示升降**（規則）：延遲、錯誤率、成本、流失、回覆時間下降才是好。往壞的方向變，數字用 `--negative`；往好的方向是 `--positive` 或灰色。盲測中評審把錯誤增加 2.5 倍卻和流量增加用同一種灰，讀成隱瞞畫面上唯一的壞消息。
- **零或無法比較的變化用灰色**：前期為零寫「+4（新）」，沒有可比較的就在變化量位置放一個短灰色破折號。研究最常見的 KPI 失敗是把零或未定義的變化當成訊號（三個一樣的綠色「上升 100%」、「>999%」、粗紅的「0.00%」）。

## 6. 圖表

### 6.1 哪種問題用哪種圖

| 問題 | 形式 |
|---|---|
| 隨時間在變嗎？ | 一條線；面積只在填色 15% 以下時用 |
| 每期多少？ | 直角長條 |
| 怎麼分布？ | 等寬區間的直方圖 |
| 誰排前面？ | 排序過的橫向長條清單，或「列的底色就是長條」的單一數值清單 |
| 佔多少比例？ | 細環，或 100% 堆疊長條（2px 縫）；最多五份 |
| 離目標多遠？ | 進度條，兩端都標，填色是真實比例 |
| 方案用掉多少？（規則） | 一條方案長度的軌道，已用填滿、已承諾用淺色段、超支超出軌道末端用負向色 |
| 偏離目標了嗎？（規則） | 每部分一列：目前比例的長條＋目標位置 1px 刻度；不要用兩條堆疊長條比 |
| 在哪裡？ | 地圖＋旁邊清單，清單承載數值 |
| 誰哪天不在？（規則） | 人×日的時間軸，每種請假各有自己的標記 |

只有幾個數字時不畫圖。同一畫面裡「每期長條＋累積總數」這種配對最多一次，且只在累積值穿過重要門檻時用。大部分時間是平的序列，最多三分之二寬、約 140px 高，或把範圍上限設在參考線約兩倍、超出的尖峰另外標出。**預測不是事實**：今天之後虛線，並標出終值。需求要求隨時間看的東西要畫在首屏。

### 6.2 一個問題、一條序列

每張圖一條序列是常態，最多三條。要看另一個指標，用控制項切換（分段控制、下拉選單、把 KPI 當分頁籤），不要疊線。圖高 112–264px（中位數約 195），寬 316–1136px（中位數約 570）。

### 6.3 軸與格線

- **格線**：只畫水平線最常見；3–5 條、1px 實線、亮色約 `#e5e5e5`、暗色（#111 底）約 `#2b2b2b`。虛線只准出現在圖表格線，畫面其他地方都不准。
- **沒有 y 軸線**；基線是唯一較重的線。
- **y 刻度** 4–7 個（中位數 5）、11–16px（中位數 12）灰色；整齊的偶數間距（0/5/10/15%）；最上面的刻度高於最大值；計數用整數；長條與計數以零為基線。**不可沒有刻度**（只在 hover 才看得到數值的被標記），也不要不等距的刻度、計數上出現 0.8、最高刻度剛好等於最大值讓線撞到圖頂。
- **軸文字不比資料大**。
- **x 標籤** 4–8 個、水平不旋轉、首尾收在圖內、全程同一間距；選一個剛好落在終點的間距，或終點不標。不規則日期要用時間軸而不是類別軸。

### 6.4 圖形

- **線** 1–3px（中位數 2），**直線段**——平滑曲線會在每日總數之間捏造數值；不放資料點標記，只有 hover 點。
- **填色**：10 張時間圖中 7 張不填；要填最多約 14% 平塗，或從線往下 150–200px 漸淡到透明。
- **長條**直角，或最多 4px 頂部圓角、底部在基線上保持直角；堆疊段以 1–2px 縫分開。
- **顏色**：每張圖一個色相；資料墨水多數不到像素的 3%。中性色序列完全可以、常常更好。畫面有一個色相時，它放在主要資料元素上。同一個對象全畫面同一色相（同一群訂閱者這張圖粉紅、下一張靛藍會被標記）。不相干的色相出現三五個一律被標記；狀態色只表狀態；全畫面最多四個色相。
- **圖例**：單一序列不放（標題或下拉選單已經說了）；否則最多五項，5–8px 圓點＋12–14px 灰色標籤放在卡片標頭，或做成小表格（點、名稱、數值、變化）讓圖例也承載資料。不列沒有資料的序列。每個色票就是它說明的那個圖形縮小。
- **環**只用在三到五部分、且旁邊沒列出的整體；不在切片上標字，總數放中心或旁邊；細描邊（90–154px 的環用 3–5px）。
- **進度條** 4–24px 高（中位數 8）、全圓角、兩端都標；零不留殘段。
- **Tooltip**：純文字或無箭頭的素面框，標籤與數值一行。
- **註記重要事件**：比平常變化大約三倍以上的跳升或尖峰，加 1px 標記與 12px 標籤寫出原因（「部署 a3f09c1」「電子報推薦」）；參考線（預算、SLO、開始時間）用 1px 虛線、標籤在末端。盲測中，沒解釋的跳升是評審第一個問的。
- **標籤不碰撞**：註記標籤排在圖上方的列，各自在引線頂端旁；沒有標籤時不保留空帶；字體載入後才排版。
- **短的、空的歷史誠實畫**：一條平的零線加一個尖峰、空期間就沒有長條、不加墊高的 y 範圍、不放「無資料」插圖；但不要讓一個點佔畫面最大的圖。

ECharts／Chart.js 的對應設定見 [patterns-advanced.md](patterns-advanced.md#資料視覺化樣板)。

## 7. 表格與清單

- **列高**：單行資料列 36–53px（中位數 45）；帶媒體的兩行列 56–92px（中位數 72）；卡內鍵值列 21–32px。兩行標籤的列距至少 40–44px；第二行約低 21px、小一級（12–14px）、灰色。總覽清單顯示 2–5 列。
- **表頭** 11–14px（中位數 12）、一般字重、灰色、**一般大小寫**（研究唯一的大寫表頭被標記為比資料吵）；**沒有底色帶**（11 個 0 個），多數表頭下沒有線；數字欄表頭靠右、與數值齊；排序符號只在目前排序的欄。
- **沒有斑馬紋**（23 個 0 個）。約一半清單沒有列分隔線，靠 61–92px 列距或填色列之間 2–8px 間隙；有線時 1px、比表面深 3–7%。
- **數字靠右、等寬數字**（`tabular-nums`）；每個指標固定小數位數（金額 2、百分比 1 或 2、計數 0）；處處有千分位；只在容量列縮寫（「12.7k / 20.0k」）；每個變化都帶正負號；貨幣符號後不留空格。
- **識別欄最寬**（表格的三分之一到一半），桌機寬度下絕不是被截斷的那欄：先編輯式縮短名稱（去掉每列都相同的發行者、「有限公司」），各寬度用同一個短名。
- **每列或每張卡一條右緣**：卡內所有靠右的數字結束在同一條內距線。
- **兩個量疊在同一格**而不是佔兩欄：計數上、12px 灰色百分比下，兩行同一右緣。
- 比較用的日期用 ISO 形式並靠右（2024-02-15）；表示新舊用文字（「今天」「昨天」「6 天」）。ID 用等寬字、內文尺寸、約 8 字元後截斷加刪節號與複製 icon。截斷成一行加刪節號，絕不在字中間斷。
- **列內的墨色**：只有識別與關鍵數字用主墨色，其餘灰色；缺值灰色破折號、真的零照印；正負號放在文字裡不靠顏色（收入綠色帶「+」、支出用墨色，不是每個負數都紅）；連結色只在名稱格、不加底線。
- **狀態膠囊** 15–28px 高（中位數 20）、文字不小於 11px、500 字重；淡色底配同色相深色字（如 `#dcfae5`／`#04250e`、`#ffedea`／`#831c1e`）。中性狀態用單色加 glyph。飽和底白字只給那一個行動呼籲且要少見（可見列超過約五分之一帶它，就變成一條黑塊）。**每列一個狀態標記**；膠囊 `flex: none; white-space: nowrap`，絕不被擠扁。
- **媒體**：密集列 16px logo、24–32px 頭像、兩行列 48–50px；人、代幣、公司用圓形，作品與旗幟 2–3px 圓角，照片 8px；整列同一個固定媒體欄，文字從同一緣開始。
- **總覽不分頁**（23 個 0 個）：限列數、在區塊標頭放「查看全部」、寫出總數。列動作：多數沒有；有就最右一個 kebab。需要處理的列（要付的帳單、要打包的訂單），動作是固定尾欄裡看得見的幽靈按鈕或墨色文字動作，每列同列距；絕不是灰字。勾選框只在有批次動作時。
- **完整清單畫面**（規則）：表格上方寫總數、捲動時表頭保持可見、結尾分頁或載入更多並顯示範圍（「1–50／1,284」）。
- **承載資料的清單**：「列的底色就是長條」只用在單一數值的排名清單；行內長條細且灰（2–3px），除非是畫面主序列；比較要畫在同一條軸上，不是只用一行字說。

## 8. 表單與設定

（研究只有三個表單與一個設定頁，這節是預設值。）

- **標籤在欄位上方**，14px／500、間距 8–10px；不用浮動標籤，也不用 placeholder 代替標籤。
- **輸入框**表單內 38–40px（圓角 8–10）；工具列與篩選控制項 28–40px（中位數 32）；同一情境一種高度。灰色面板上的輸入框仍是白底 1px 淡框；篩選與下拉控制項框線再深一階。
- **間距**：說明到第一個標籤 24px、欄位之間 16px、到儲存按鈕 16px。
- **開關** 28×16 到 33×20；開啟色用語意綠或近黑，不用品牌強調色。
- **停用的控制項要看得清楚並說明為什麼停用**（研究中 1.4:1 的停用按鈕、30% 不透明度的鎖定面板被標記為不可讀）。
- **設定版面**：每一段是一列——左側標籤欄（約 450px：16／500 標題＋14px 灰色說明）、右側面板（約 700px、淡底、圓角、無框無影）；段落之間全寬 1px 線、上下各 32px。標籤欄不要在高面板旁留空（放該段說明或目前值的摘要，或縮窄欄）。
- **破壞性動作**（規則）放最後、自成一段，用負向色的文字或外框按鈕，用文字寫出後果，確認時點出物件名稱。
- **一個區域一個畫面**（規則）：設定跨多個區域（一般、成員、帳務、通知）時，每個側欄項目開自己的畫面（靜態原型用 hash 路由即可），區域名稱當 `h1`；不要一長頁全部區域加錨點捲動。
- **一個畫面一種儲存模型**：每個控制項各自儲存並顯示安靜的「已儲存」，或每個面板右下一個儲存按鈕；不在同一畫面混用。
- **顯示設定會產生什麼**：控制項旁放結果的小預覽（邀請信、通知抵達的樣子、下一張帳單）。
- **按鈕**：控制項 27–40px 高（中位數 34）；緊湊風格 6–8px 圓角、柔和風格全膠囊；每畫面一個實心主要按鈕（通常近黑）、次要白底 1px 框、第三級純文字；同一列控制項同高。

## 9. 字體與配色

### 9.1 字體

- **一個無襯線字族**（研究 23 個全是 neo-grotesk、14 個只用它）。第二字體只有一個工作：等寬字給所有數字或只給 ID、襯線字給一句問候、品牌字只用在字標或切換器。絕不三種。軸刻度、圖表註記、標籤即使 ID 用等寬，也維持內文字體。字體選擇程序見 [patterns-advanced.md](patterns-advanced.md#字體選擇程序)。
- **工作畫面的字不是顯示字**：`h1` 18–32px，沒有數字達 48px。盲測中 50px 襯線標題和 76px 餘額讓預算畫面讀起來像登陸頁。

| 角色 | 研究範圍 | 中位數 |
|---|---|---|
| 頁面標題 | 14–48 | 24 |
| KPI 數值 | 16–40 | 24 |
| 卡片標題（500–600） | 14–24 | 16 |
| 內文、導覽、儲存格 | 13–16 | 14 |
| 標籤、中繼資訊 | 11–14 | 12 |
| 軸刻度 | 11–16 | 12 |
| 膠囊、徽章 | 9–14 | 11–12（下限 11） |

最乾淨的級數是 12/14/18/24、12/14/16/30、12/14/16/24；一個畫面 4–9 種尺寸（中位數 6）、字重中位數 3 種、700 只做一件事（金額、問候或標題）。表格、KPI 與會更新的數字一律等寬數字，並確認該字體的 `tabular-nums` 真的改變了數字寬度，沒有就換字體。一般大小寫；字距 0，只在大字用負字距（32px 用 -0.02em）；14px 文字行高 20px、16px 行高 24px。

### 9.2 亮色畫面的配色

- **底的模型**：淡灰底上白卡（10 個，約 #f3f5f7–#fdfdfd）、白底上灰面板（6 個）、框起的紙面（7 個）。側欄絕不深色或飽和。
- **線分三階**：卡片邊約 `#eaeaea`（工作範圍 #e5e7eb–#ededed，對白底約 1.2:1）；列分隔線淺一階（#efefef–#f4f4f4）；控制項框深一階（約 #d1d5db）。
- **文字分三階**：主要約 `#111`；次要約 `#606060`；研究中的第三階與 placeholder 只有 2.5–3:1，在截圖上就已讀不清——**每一階承載文字的顏色都要在它所在的表面讀得清**，placeholder 也是；4.5:1 是參考值，需做無障礙時為合規門檻（主檔〈受眾分級〉）。`#6b6b6b` 大約是白底與 `#f9fafb` 上還達 4.5:1 的最淺灰。
- **強調色的位置**：只在資料上（外殼全灰階）、只在動作上，或完全不用；多於一個強調色族的畫面都被標記。
- **狀態色**：研究中的正向綠（#16a34a–#40a670）當文字不到 4.5:1，文字改用較深的綠如 `#247b50`（5.2:1）；膠囊用淡色配對（正向 `#dcfae5`／`#04250e`、負向 `#ffedea`／`#831c1e`、提醒 `#fffbeb` 底 `#fde68a` 框 `#92400e` 字）。

### 9.3 暗色畫面的配色

- **底**：`#000`、`#111` 或 `#171719`。**不用海軍藍、不用板岩藍。**
- **表面**：無框的亮一階（#000 上 #111，巢狀面板 #222–#2a2a2a），或底色本身＋1px 線（#111 上 #2e2e2e）。結構線比底亮 22–31 階；可互動外框更亮（#373737–#4c4c4c），讓外框按鈕不靠填色也看得出可點。
- **文字**：`#fff`；次要約 `#b4b4b4`、中繼約 `#949494`——最多兩種灰，且差得夠遠（#aaaaaa、#969696、#bbbbbb 同時出現會讀成同一種灰）；同樣要讀得清，以 4.5:1 為參考（需做無障礙時為門檻）。
- **強調色**只在資料上或一個選中狀態；導覽選中靠亮度。狀態色是色相配它自己的深色淡底（`#3fc07a` 在 `#172a1d`）。**強調色是綠或黃綠時，`--positive` 就用強調色**，否則畫面上會有兩種綠。
- 帶色像素佔比 3% 以下（研究 6 個全部）。

### 9.4 表面、圓角、icon、間距

- **邊**：框線或陰影，**絕不兩者都用**；存在的陰影都很淡（約 0 2px 8px、alpha .06 以下）；真正的陰影只給浮起的東西（選單、popover、tooltip、對話框）。
- **圓角是雙峰的**：緊（4–8px）或柔（16–24px），11–12px 很少；控制項跟著卡片（緊卡配 6px、柔卡配全膠囊）；巢狀圓角往內遞減（20、10、8、5、4）。
- **成組，不要成盒**：一組 KPI 是一張以 1px 分隔線切開的卡，或一條無框帶 48–52px 垂直分隔線。
- **icon**：線框；導覽 14–20px（中位數 16）、約 1.5px；行內 12–14px；距標籤約 10px；灰色。絕不放在飽和圓圈裡；容器若有，是中性的。
- **間距**以 4px 為基：卡片間距 6–24px（中位數 16）、卡片內距 12–34px（中位數 20）、區段間距 24–64px、控制項高 27–40px（中位數 34）。

## 10. 密度

研究中的畫面有 6 到約 120 個資料點（中位數約 25）：

| 密度 | 資料點 | 卡片內距 | 列高 | 內文 |
|---|---|---|---|---|
| 稀疏（首頁、設定、單一物件） | 6–25 | 20–24px | 56–92px | 14–16px |
| 中等（分析總覽、財務首頁、清單） | 25–50 | 16–24px | 44–56px | — |
| 密集（研究、監控、長時間使用） | 約 120 | 32px | 清單 28px、表格 42px | 13px，外圍留大量空氣（100px gutter、帶與帶之間 64px） |

密度是三個設定一起動：列距、內距、字級；不要只縮字而保留內距。**被放置的空間讀起來是平靜，剩下的空間讀起來是沒做完**：空白來自固定格線與重複間距才像刻意；來自不配資料的格線、每列都空的欄、大半空的頂列、被拉長的卡片就是意外。為帳戶現在有的資料設計，也為它將來會有的設計：區塊大小依問題，不依產品期望的資料量。

## 11. 零值、空、載入、錯誤

- **真的零**照一般樣式印：「$0」「0」「0%」「0.00%」。零可以變灰，當旁邊的說明變成下一步時。
- **缺值或不適用**是灰色破折號；絕不用內文數值尺寸的「--」（24px 的「--」讀起來像載入中）。
- **計數跟著視圖，外框也是**：分頁籤、KPI、「12 筆未結」這類範圍內的計數，由目前視圖或篩選的列算出、每次切換重算。篩選後的區塊縮到它的列數，或保持固定列數並用一句空狀態填空列。
- **空的側卡用參考資料填**，不是 400px 白底裡一個虛線框：還沒有東西售罄前，在「今天還沒有售罄」下列出上週日的售罄時間。
- **紅色是訊號不是紋理**：每個物件最多一個紅色標記，放在逾期或失敗的那個事實上。
- **空區塊保留外框與標頭**，加一句橫跨整塊的話（在列格線裡用 `grid-column: 1 / -1`，擠在 34px 欄裡會逐字斷行）：約 38px 高的 1px 虛線框（「此期間沒有通路用量。」），或帶新增連結的框。
- **空的圖照樣畫**：零線、空期間沒有長條、不墊高範圍、不放插圖。
- **首次使用**（整個畫面空）：保留外框與標題，把第一個動作放在資料將出現的地方；有設定步驟就顯示真實百分比的進度。
- **載入**（規則）：最終版面，每個數值換成真實尺寸的平塗灰條（24px 的數值配 24px 高的條、列距不變），標籤與表頭立即顯示，**沒有閃光漸層**，資料到時版面不位移。已在畫面上的資料重新整理時保留舊值、更新時間戳記。
- **錯誤**（規則）：在失敗的那一塊裡，絕不是全螢幕橫幅。一句話寫出什麼失敗、資料最後一次正常是何時（「無法載入部署。最後更新 09:14。」），加一個「重試」文字按鈕；負向色只用在小 icon 或膠囊配對。
- **過期或靜態資料**：時間戳記加重新整理按鈕；不能重新整理的快照用一則安靜的提醒說明一次。提醒的淡色絕不當底色。
- **限額與用量**：真實比例的長條、兩端都標（「12.7k／20.0k」）。

## 12. 手機（規則；研究沒有手機畫面）

- **導覽收合**：側欄變成 48px 頂列（畫面名稱、開啟全螢幕面板的選單按鈕、最多一個動作），或四到五個目的地的底部列。手機上側欄仍佔超過 30% 寬就是失敗。
- 邊距 16–20px；觸控目標約 44px 高（需做無障礙時 44×44 為合規門檻）；資料與標籤 14px、副標不小於 12px。
- **標題留著**，20–24px；標頭動作收進 kebab，主要動作除外。
- **篩選**收成一列 chip 或「篩選」面板；分頁籤在自己的列內橫向捲動，不是整頁捲動。第一列清單在手機畫面上方 60% 內開始。
- **KPI**：分隔容器變兩欄格或「左標籤、右數值」的清單，絕不擠成四欄；兩欄格在任何全寬領頭項之後的數量要是偶數，否則用三窄欄、分隔清單，或讓最後一格全寬。
- **圖表上方最多一列控制項**；圖全寬、160–200px 高、3–4 個 x 標籤、圖例圓點放上方；y 刻度有自己的通道，刻度標籤絕不壓在線上。
- **手機上的列動作**是文字動作或一個緊湊的尾端按鈕，清單一個實心批次動作。
- **表格在約 640px 以下變兩行列清單**：第一行是識別與關鍵數字、第二行是需求點名的其他欄位（13px 灰色）、右側一個動作；欄位移到第二行，絕不丟掉。必須保持表格的，在自己的框內橫向捲動並固定第一欄；**頁面絕不橫向捲動**。
- **平板（641–1100px）是自己的一段**：側欄收成頂列，但表格保留四到五欄、次要欄位成副標；兩個窄面板任一會窄於約 340px 時就堆疊；識別欄絕不是被截斷的那欄。
- **帶動作的區塊往上移，不往下**：右欄的低庫存與補貨、到期帳單與付款，變成清單上方一行摘要（「5 項庫存偏低・查看」）。
- 多窗格（清單與詳情、收件匣）一次一個區域；選一列推入詳情、返回時回到原捲動位置。設定的標籤欄堆在面板上方；右欄移到主欄下方或一個分頁籤。

## 13. 工作畫面放寬的規則、仍然禁止的

主檔的「預設禁令」是為只讀一次的頁面寫的；工作畫面每天被使用，那些禁令裡有一部分正是工作畫面的結構。以下放寬，各有上限：

| 工作畫面允許 | 上限 |
|---|---|
| 卡片、面板、表格、控制項的 **1px 框線** | 亮色約 1.1–1.3:1（白底上 #e5e7eb–#ededed）；暗色 #000 上 #1a1a1a、#111 上 #2e2e2e；控制項深一階。框線或陰影，絕不兩者。 |
| 表格與清單的**列分隔線** | 1px、比表面深 3–7%；無斑馬紋、無表頭色帶 |
| **虛線** | 只在圖表格線與空槽位 |
| 數值上方的**小標籤** | 12–14px、一般大小寫、灰色讀得清（參考 4.5:1）；中繼與軸文字 11–12px；不小於 11px；全畫面最多一個字距加寬的大寫標籤 |
| **一排相同的卡片** | 只給同類指標或同類物件：3–6 個、等寬、一個間距、無落單、跨列邊緣對齊、頂部無 icon；優先用一張分隔的卡 |
| **等寬字** | ID、金鑰、程式碼；或作為一種風格決定給所有數字；其他地方用內文字體的等寬數字 |
| **膠囊** | 只在列內與數值旁：16–24px 高、淡色底配同色相深色字；絕不在標題上方 |
| **編號** | 只當資料：排名「1.」、節點編號 |
| **icon** | 14–20px 線框、一套、灰色：在導覽、標籤前，或單一功能（kebab、chevron、資訊）；容器只能是中性的 |
| **陰影** | 浮起的東西：選單、popover、tooltip、輸入器、對話框；靜止卡片最多一個小於 8% 黑的小模糊 |
| **第二種字體** | 只做一件事：等寬給 ID 或數字、襯線給一句問候 |
| **漸層** | 只當一條折線圖下的面積漸淡；約 14% 平塗更安全 |

仍然禁止（與頁面相同）：

| 禁止 | 改用 |
|---|---|
| 底、按鈕、卡片、文字、KPI 磚上的漸層 | 平塗 |
| 光暈、玻璃、背景模糊 | 與底差一階色的不透明表面 |
| 每個 KPI 或卡片上放彩色圓圈或淡色方塊 icon | 一個標籤一個數字 |
| 彩虹圖：超過四個色相、每根長條一個色相、同一對象兩種色相 | 每張圖一個色相，其餘中性 |
| KPI 上的迷你走勢線 | 趨勢放自己的圖，或不放 |
| 問候、標籤、導覽、空狀態裡的 emoji | 文字 |
| Lorem ipsum、Acme、John Doe、「使用者 1」；虛榮數字（「10,000+ 團隊」）；加不攏的總數 | 使用者提供的資料、由明細算出的總數；缺的依主檔「缺資料」規則以標明的 placeholder 呈現 |
| 零或未定義的變化用狀態色 | 灰色，或用文字寫出（「+4（新）」） |
| 亮色畫面配深色或飽和側欄；海軍藍或板岩藍的暗色主題 | 側欄用頁面底色；真正中性的暗色 |
| 強調色用在外殼：帶色導覽列加左側條、彩色分頁籤膠囊、每顆按鈕品牌色 | 強調色在資料與最多一個控制項；近黑的主要按鈕 |
| 大寫加字距的表頭、斑馬紋、表頭色帶 | 12px 灰色一般大小寫表頭；線或空間 |
| 數字靠左、欄內比例數字 | 靠右的等寬數字 |
| 主視覺式標題、帶 emoji 的問候、插畫歡迎橫幅 | 24px 名詞標題 |
| 五列的總覽清單下面放分頁 | 限列數、「查看全部」、總數 |
| 紫、靛色強調；奶油底配赤陶 | 依配色程序取色 |
| 登陸頁式標題（超過 32px）或 48px 以上的數字 | 18–32px 標題；16–40px 數字 |
| 清單每列或每張同類卡頂端重複的方塊 icon | 需要時一個 16px 素 icon，或不放 |
| 每列一個色相、每列預算的「剩餘」都是綠色 | 正常的用灰色，只有有風險或超支的列上色 |
| 叫不出產品名、沒有任何動作的畫面 | 外殼裡有產品標記與範圍；主要任務一鍵可達 |

## 14. 生成儀表板的破綻對照表

| 破綻 | 真的產品畫面怎麼做 |
|---|---|
| 深海軍藍或帶色側欄，選中項是彩色膠囊加左側條 | 側欄在頁面底色上；中性灰膠囊，或暗色時標籤變亮 |
| 「歡迎回來，Alex 👋」加副標 | 24／600 的名詞標題 |
| 四張 KPI 卡各一個淡色圓圈 icon | 一個容器以分隔線切開，標籤在數值上方 |
| 每個 KPI 都有綠色「+12.5%」膠囊 | 23 個中 9 個有變化量，用文字寫出窗口；零用灰色；從零起寫「+4（新）」 |
| 每個 KPI 都有迷你走勢線 | 0 個；趨勢有自己的圖 |
| KPI 數值 36–48px、粗體、品牌色 | 24–30px、400–600、墨色 |
| 平滑曲線的漸層面積圖、每個點都有圓點 | 2px 直線段，10 張中 7 張不填色，不放點 |

| 每 20px 一條格線、兩側都有軸線、單一序列也有圖例 | 3–5 條淡線、無 y 軸線、單一序列無圖例、刻度整齊且高於最大值 |
| 粗甜甜圈、切片上有字、洞裡一個大總數 | 細環、切片無字、圖例做成帶數值的表格 |
| 16–24px 圓角卡片＋1px 框＋大片柔和陰影 | 框線或色階、無陰影；緊或柔的圓角選一次 |
| 大寫表頭的斑馬紋表格，每列都有勾選框、頭像、狀態 chip、kebab | 線與對齊：12px 灰色表頭、一個狀態標記、需要處才有一個動作 |
| 靠左的比例數字 | 靠右的等寬數字、固定小數、灰色單位 |
| 飽和狀態 chip 配白字 | 淡色底配同色相深色字 |
| 每顆按鈕、分頁籤、連結都是強調色 | 23 個中 12 個沒有實心主要按鈕；有的話是近黑 |
| 每個畫面都有搜尋、鈴鐺、頭像的頂列，或一條大半空的頂列 | 23 個中 9 個沒有頂列；有就承載搜尋、切換器或物件名 |
| 標題旁擠著匯出、分享、日期選擇器 | 只放真的動作；改放更新時間戳記 |
| 假人名假公司、整數虛榮總數、一週大的帳戶卻有成長曲線 | 使用者提供的資料、小數字照實際大小、總數由列加總 |
| 不管資料多少都是等寬四欄格、落單格子、被拉長的卡 | 欄數由項目數決定；跨欄寬度隨列變化但落在同幾條線上 |

| 清單每個類別一個彩色 icon | 一套灰色 icon；若要顏色，放在數字上 |
| 空圖表放插圖與「尚無資料」 | 畫出零線，框內一句話 |

每個破綻都拿掉、卻什麼都沒放回去的畫面，是一個整齊的模板。填滿空間的是產品：它自己真實尺寸的資料、用最大區塊回答的那個問題、加得攏的格線。
