# 功能指引圖製作規範

**定位**:功能指引圖是放在報告或手冊內之**畫面概覽圖**:一張圖取一頁之全畫面,以紅框圈出各功能區,以灰色引線接到四周之功能文字,說明「這一頁有哪些功能、叫什麼」.它含既有之功能,不是成果展示.排版規則(間距、順序、避讓)已由自有套件 w-guidechart 實作;本技能管何時用,取景與量框怎麼選,規則之意義,設定檔怎麼寫,以及套件回答不了之部分(框得對不對、名稱對不對,須逐張目視).

**名詞**:「功能區」指畫面上要指引之一塊(按鈕列、清單、圖組等);「框」為圈選功能區之紅框;「引線」為自框緣出發之灰色斜線;「水平線」為引線所接、其上寫功能文字之灰色橫線;「層」為截圖上方或下方放水平線之一排(每側至多 4 層);「起點」為引線自框緣出發之點;「接點」為引線與水平線相接之端;「文字區」為水平線全長(文字寬＋2×`layout.pad`〔8〕,下方層另含規則 9 之避讓).

**本技能依 w-guidechart 1.0.1 撰寫**:鍵名、預設值與介面以套件為準;套件升版後以其 README 與 `WGuidechart.defaultStyle`、`WGuidechart.defaultLayout` 核對,本技能與之不符時以套件為準並通報修正(全域設定 §13).

**與其他技能之分工**:

| 情境 | 技能 |
|---|---|
| 亮點展示圖(固定畫布,一圖一主張) | skill[role-design-web-for-showcase] |
| 操作手冊之標準圖(每步一張,一個紅框,由 e2e 測試產製) | skill[role-coder-for-test-e2e]、skill[role-writer-report-e2e-to-manual] |
| 功能指引圖之圖名與引圖句之寫法 | skill[role-writer-report-final](〈亮點與配圖〉第 5,6 節);落點與是否使用見本技能 §1 |
| 標籤與圖名之用字、禁詞 | 專案之報告撰寫規則與 lint(§6) |
| 對指引圖之框,灰線,文字位置與間距不滿(「重新設計」) | 走本技能(§5 規則與 §8 覆寫);不走 skill[role-design-web-for-redesign],該技能管既有 production 系統之 UI |

## 0. 五條鐵則

1. **全畫面取景**;只有疊圖才裁(§3).
2. **框住可見內容之聯集**,不框空白;框不切過圖示,線不壓字(§4).
3. **排版交給套件之規則**;個案以功能區覆寫處理並寫理由,先改全域規則讓多數圖變好,再處理個案(§8).
4. **自動檢核只回答幾何**;框得對不對,名稱對不對,逐張以原尺寸目視(§7).
5. **本圖含既有功能,不當成本期成果**(§1).

## 1. 定位與在報告中之落點

- 成果類報告中,功能指引圖置於各節介紹完本期成果之後,以「當前之畫面」帶出,並於引圖句說明圖中以紅框圈選功能區、以引線註明其功能.引圖句為段落最後成分,圖內說明接在引圖短語之後,圖名末字為「圖」且全報告不重複,寫法依 skill[role-writer-report-final]〈亮點與配圖〉第 5,6 節.該圖類不在該技能專案參數第 23 項所列之圖類內,是否使用由裁定者或專案決定;無裁定者列入待裁示.
- 圖名預設「○○之功能指引圖」.
- 裁定者指定沿用某份既有圖之呈現方法時,先量該圖之樣式(框色、線寬、引線色、字型與字級),以 `style` 覆寫(§8);排版仍依本技能之規則.專案另有裁定者從專案.

## 2. 樣式(預設值;皆可覆寫,以 `WGuidechart.defaultStyle` 為準)

- 截圖以原尺寸嵌入,不縮放;加柔和之陰影(`shadow`:下移 `dy` 4、模糊 `blur` 10〔高斯模糊之標準差〕、黑色、不透明度 `opacity` 0.35),使白底頁面之截圖有邊界.`shadow: null` 為不加.
- 框:紅 `#FF0606`(`frame`)、線寬 5(`frameW`)、無填色.
- 引線與水平線:灰 `#999999`(`lead`)、線寬 3(`leadW`).引線自起點至接點為一段斜線,接點預設為水平線之**左端**(灰線往右轉,`join: 'l'`);`'r'` 為右端,`'auto'` 擇引線較短者.水平線長約等於文字寬.
- 功能文字:`Microsoft JhengHei`(微軟正黑體,`font`)、黑字(`textColor`)、36 像素(`fs`;以 1600 寬之全畫面截圖為準),置於水平線上方,文字基線距水平線 12 像素(`layout.base`).
- 畫布寬(未指定 `canvasW` 時)＝截圖寬＋2×`ext`:`ext` 預設 100,1600 寬之截圖為 1800.各圖畫布寬相同,放入報告後字級才一致;各圖截圖寬不同(含疊圖裁切)時,以 `canvasW` 統一(須不小於各圖所需,較窄者左右補白).畫布超出層總寬者(左右側之標籤、超出層範圍之水平線,或 `ext` 小於陰影外溢量),套件列問題 `CANVAS_TOO_WIDE`.

## 3. 取景

- **以全畫面為主**:只有疊圖時,疊圖之部分才允許以 `views[].crop` 裁取重要區域.裁切後之圖寬度小,放入報告後畫面過小,也不利排列引線與功能文字.`crop` 為 `[x1, y1, x2, y2]`(截圖座標之整數,x1<x2、y1<y2;格式不合者視為未給,即全畫面);超出截圖,或有功能區落在裁切外,reject `E_CROP`.
- 截取**不含紅框**之畫面(套件之截圖本即不含框);操作手冊之標準圖已帶紅框,不可沿用.
- 預設視窗 1600×900、`deviceScaleFactor` 1;自備 `env.openPage` 時視窗須固定且 `deviceScaleFactor` 為 1,否則 `E_OPEN`.
- **取景前滑鼠停於不影響畫面處**:`capture.mousePark` 預設 `[1000, 4]`,`null` 為不停放;避免停留提示與 hover 樣式.
- **等畫面穩定**:資料載完、動畫停止由 `open` 自等(套件不知道頁面要等什麼).套件另於取景前等字型就緒與連續兩次截圖相同(`capture.settle: 'stable'`,預設);頁面有持續動畫(輪播、載入中圖示)者,先在 `open` 內停掉,不得已才改 `settle: 'fonts'`(只等字型就緒與雙 rAF,略過連續兩次截圖相同之比對).`capture.settleMs` 是穩定等待之**上限**(預設 5000,不是固定等待;兩種 `settle` 皆適用),逾時 reject `E_SETTLE`;逾時先查動畫與載入,不先加大上限.
- 取景之頁面與狀態以可重現之方式開啟(例:回放既有端對端測試之錄製資料,不連正式環境),使重繪時畫面不變.

## 4. 框

1. 框住**可見內容之聯集**再外擴,不框整欄或整區之空白.可見內容含:文字、圖片、svg、canvas、輸入元件、字型圖示,以及有底色、漸層底(`background-image`)、邊框或陰影而小於容器一半之元素;此類裝飾元素之高或寬不足 4 像素者(分隔線)不算內容.
2. 框與框不相疊,間距至少 6 像素(否則 `BOX_TOO_CLOSE`);框夾於畫面內(距邊至少 3 像素).
3. 框不切過圖示(漸層底之圖示底塊亦須計入),框線不壓字.相鄰 2 功能區之內容間距不足以容納雙方外擴與框線時,分框必有一框壓字者(例:互動圖之標題緊接於其上之設定列),合為一框並以「甲與乙」命名.
4. 以頁面內之 DOM 量測,不寫死座標.`find` 有四種寫法(恰給其一):

| 寫法 | 意義 | 何時用 |
|---|---|---|
| `{ sel }` | 第一個可見之符合元素 | 有穩定選擇器 |
| `{ at: [x, y], minW?, minH? }` | 該點之元素往上第一個寬高皆達門檻之祖先 | 無穩定選擇器,以點位取祖先 |
| `{ fn, arg? }` | 於頁面內執行之函數,回傳 `{ x1, y1, x2, y2 }` 或 `null` | 自訂矩形;`fn` 須自足,不可引用外部變數(經 `page.evaluate(fn, arg)` 序列化),所需參數經 `arg` 傳入(只收原始值、陣列、一般物件、Date;含存取器、循環、函數者視為未給,`fn` 將無參數執行) |
| `{ union: [find, ...] }` | 各者之聯集 | 一個功能區由數個分離之元素組成;**任一成員量不到即 reject `E_BOX_NOT_FOUND`**,不會略過該成員;`pad` 只認最外層,`mode` 由各成員自己決定 |

   另可帶 `mode`:`'fit'`(預設,可見內容之聯集)或 `'box'`(元素外框);**`fit` 只計元素內之內容(文字、子元素),不計元素自身之底色與邊框**:canvas 等無子內容者量不到(`E_BOX_NOT_FOUND`),有文字之按鈕或卡片則只框到文字範圍;要含元素自身外框者用 `mode: 'box'`.`pad` 為外擴像素,預設 fit 6、box 與 fn 2.量得之框寬或高小於 8 像素亦 `E_BOX_NOT_FOUND`;`find.fn` 回傳之矩形為視窗座標,須為有限數.

## 5. 引線與文字之排版規則

依序套用(w-guidechart 已實作;括號內為設定鍵與預設值).目的是用規則讓所有圖之間距、順序一致,個案才以覆寫處理.

1. **一律優先排上方 1 層**.不穿過他框之引線優先;無則穿過他框亦排上方.
2. **同層間距平分且左右對稱**(`spread: 'even'`):整排文字區預設排於截圖寬之內,左右兩端各留預設距離(`edge` 20).間距＝(可用寬－文字區總寬)÷(文字區數－1),首尾貼齊可用寬之兩端.一層只有 1 個標籤時,靠近其引線落點.
3. **最低間距與擴展**:文字區總寬＋(數－1)×最低間距(`minGap` 40)不超過可用寬者,全排於截圖寬內;超過時才往左右對稱擴展,至多截圖寬＋2×`ext`(`ext` 預設 100,即至多截圖寬＋200).
4. **過擠才換向**:上方 1 層已觸及最低間距且用完擴展額度,才將標籤換至下方 1 層.換向時比較換 1 至 3 個之所有組合,取上下兩層總成本最低者(每多換 1 個加罰 `movePen` 500).下方亦過擠則加層,每側至多 4 層,仍排不下為 `TIER_OVERFLOW`.上方第 1 層水平線距截圖上緣 `gapTop` 90,下方第 1 層文字頂距截圖下緣 `gapBot` 70,層距 `tierGap`(`null` 為字高＋34).
5. **同層之左右順序依引線自紅框出發之位置(起點 x)由左往右**(`orderPen` 3000).斜率隨文字之位置而變,不作為排序依據.次要:標籤順序與功能區之左右位置對應(`framePen` 200;框中心 x 相同者以上下順序對應左右).
6. **起點之框緣優先序**:上方層為上緣 → 右緣 → 左緣;下方層為底緣 → 右緣 → 左緣.前一緣不穿框到不了才用下一緣(`penRight` 1500、`penLeft` 3000;`sideEdges: true` 時才可取左右緣).左右緣取靠該層之一段,斜拉至該層.
7. **灰線原則上不穿過他框**;無法自動排入者(例:分頁列夾在頁首與內容之間,上下皆被他框擋住)才允許穿過,取穿過最少、引線最短者,列為「注意」`LEAD_THROUGH_BOX`(`crossPen` 5000).不因須穿框而改排下方.
8. **引線不貼著他框走**(30 像素內加罰,`nearM` 30、`nearPen` 300;`rayM` 12 僅用於判斷某層是否到得了,不影響最終間距)、**引線之間不相交**、標籤不相疊、水平線不超出層之範圍.
9. **下方層之文字避讓**:下方層之斜線自上方接至水平線之端,會穿過其上之文字.依斜線之角度,估算斜線於文字頂之高度偏離接點之距離,文字向接點之反方向避讓該距離再加 8 像素,水平線隨之加長,以加長後之長度重排同層;並檢核「引線遮住其功能文字」.上方層之斜線自下方而來,不穿過文字.
10. **平分後無路可走之保底**:平分後有引線過於平躺而無可用路徑(水平位移超過垂直距之 `maxSlope` 2.5 倍)者,該側(上方或下方)之標籤改為靠近引線落點(`'near'`),列為注意 `TIER_NEAR`.
11. **左右側只在功能區強制 `side` 時才排**;左側之接點在水平線右端.左右側之轉折點距截圖邊 `sideGap` 46,相鄰水平線之最小間距 `lineGap`(`null` 為字高＋26).

每圖功能區建議 ≤10;n≥12 之合成案實測會有排不下之問題.

## 6. 標籤與圖名之用字

- 標籤用畫面上之名稱,或規格(spec)〈畫面元素對照〉之名稱;描述功能而非元件型別.
- 畫面原文屬專案用字規則所禁之用語者,只能加「」引用,否則改寫為其功能.
- 標籤與圖名同受專案之撰寫要點與 lint 約束;設定檔納入 lint 之掃描範圍.
- 套件對標籤之限制:非空,且只含 XML 容許、非控制字元之碼點;字型名稱不得含引號與 `<>&;\`.
- 圖名為「○○之功能指引圖」,與報告之圖清單一致.**圖名不放 `views[].name`**:`name` 會成為輸出檔名,只收安全檔名(英數開頭,只含英數與 `. _ -`,至多 100 字元,非 Windows 保留名,不以 `.` 或 `.layout` 結尾),全部 views 唯一(不分大小寫).圖名放使用端自有之鍵(如 `cap`;套件不讀,原樣交給 `openPage`),由報告產線讀取.

## 7. 產製流程(自有套件 w-guidechart)

1. **安裝**(專案內;套件之安裝來源依全域設定 §5.1):

   ```
   npm i w-guidechart
   npm i -D playwright
   npx playwright install chromium
   ```

   套件執行期只依賴 wsemi,**不含 playwright**:使用端自備 playwright(套件以 `^1.64.1` 驗證)與其瀏覽器,於 `env.launchBrowser` 注入.離線環境:於可連網之機器以同版 playwright 執行上列指令,把其瀏覽器資料夾複製至目標機,以環境變數 `PLAYWRIGHT_BROWSERS_PATH` 指向該資料夾.套件只在 Windows 11 以 Chromium 實跑驗證;字寬以繪製時之瀏覽器量測,輸出隨瀏覽器版本與系統字型而變.

2. **設定檔**(每份報告一份;設定檔是程式碼,以使用端之權限執行):

   ```js
   import { chromium } from 'playwright'
   import WGuidechart from 'w-guidechart'

   let conf = {
       dirWork: './guide-work', //必給; shots/、data/、svg/ 置於其下
       env: { launchBrowser: () => chromium.launch() }, //必給; 取景與繪製共用, 套件用完即 close
       views: [{
           name: 'home', //必給; 安全檔名, 全部 views 唯一
           cap: '首頁之功能指引圖', //使用端自有之鍵, 套件不讀
           open: (page, helpers) => page.goto('http://localhost:8000/'), //必給; 開到取景之狀態
           regions: [
               { label: '查詢列', find: { sel: '.toolbar' } },
               { label: '清單', find: { sel: '#list', mode: 'box' } },
           ],
       }],
   }

   let res = await WGuidechart(conf, { capture: true })
   if (res.some((r) => r.issues.length > 0)) {
       process.exitCode = 1 //套件不設離開碼, 由使用端決定
   }
   ```

   - 只 `export default WGuidechart`(另有靜態 `defaultStyle`、`defaultLayout`);**沒有 `runCli`,也沒有命令列旗標**,呼叫方式為 `WGuidechart(conf, opt)`.
   - `conf`:`dirWork`(必給)、`dirPng`(選填,預設 `<dirWork>/png`)、`style?`、`layout?`、`capture?`、`env`、`views`.
   - `env`:`launchBrowser`(必給,取景與繪製共用;回傳須有 `newPage`、`close`)、`openPage(browser, view)`(選填,預設開 1600×900 之頁面;取景後套件關閉該頁所屬之 context,勿回傳與他用共享之頁面)、`helpers`(原樣交給 `open`)、`afterCapture`(例:錄製檔缺漏即中止;拋錯 → `E_OPEN`).
   - `views[]`:`name`、`open(page, helpers)`、`regions` 必給;`crop`、`style`、`layout` 選填;其餘使用端自有之鍵套件不讀.
   - `regions[]`:`label`、`find` 必給;`side`、`ax`、`anchor`、`tier`、`x`、`dx`、`join` 為排版覆寫(§8).
   - `opt`:`capture`(true 為先取景再繪製)、`names`(只處理之圖名陣列;有不存在者 `E_VIEW_NOT_FOUND`)、`debug`(true 時,選填鍵無效而被改用預設者經 `funLog('warn', { msg })` 或 `console.warn` 警告)、`funLog(label, info)`(進度 `capture`、`render` 與警告 `warn`;預設不輸出)、`onTrace(e)`(觀察回調,測試用).

3. **探測**:以頁面內列出點位之元素祖先鏈,選定 `find`(§4).
4. **取景與繪製**:`opt.capture: true` 取景(截圖與量框)後繪製;**只改排版設定(`style`、`layout`、功能區覆寫)時省略 `capture`**,沿用資料檔,不必重開頁面.改了 `find` 或增刪功能區須重新取景,否則 reject `E_STALE`(套件核對).
5. **讀結果**:`res` 每圖一筆 `{ name, w, h, issues, notes, decisions, files }`.
   - `issues`(問題,圖照常輸出)與 `notes`(注意,不擋出圖)為 `{ code, msg, regions }`(`regions` 為功能區索引),碼見 §9.**離開碼由使用端自設**(如上例以 `issues` 非空為失敗).「問題」須為 0;「注意」逐條判讀(穿框是否無法避免).
   - `decisions` 為各標籤之排版結果:`side`、`tier`、`anchor: { edge, at }`、`x`、`len`(水平線長,僅供參考)、`join`.其中 `side`、`tier`、`anchor`、`x`、`join` 可照抄為覆寫值;`anchor.at` 為 `null` 者不可照抄(覆寫之 `at` 須為 0～1,否則整個 `anchor` 視為未給).
   - `files`:`shot`(不含框之截圖)、`data`(各功能區之框,供只改排版時沿用)、`layout`、`svg`(內嵌截圖並加陰影,可再以 Inkscape 微調)、`png`.
6. **逐張以原尺寸目視**:檢查框是否切過圖示、框線是否壓字、引線是否過長而難以對應、標籤是否對得上功能區.自動檢核只回答幾何,回答不了框得對不對、名稱對不對.
7. 報告之圖清單引用產出之 png,重產報告.

## 8. 設定之覆寫

優先序:功能區 ＞ 各圖 ＞ 設定檔全域 ＞ 套件預設.**選填鍵給了而無效者不 reject,視為未給、改用預設**(用 `opt.debug` 看警告);必給鍵(`dirWork`、`env.launchBrowser`、`name`、`open`、`regions`、`label`、`find`)無效則 reject `E_ARG`.

| 層 | 鍵 |
|---|---|
| 全域、各圖之 `style` | `frame`、`frameW`、`lead`、`leadW`、`font`、`fs`、`textColor`、`shadow`(`null` 為不加;物件逐鍵與繼承者合併) |
| 全域、各圖之 `layout` | `spread`、`edge`、`minGap`、`ext`、`join`、`gapTop`、`gapBot`、`tierGap`、`maxSlope`、`rayM`、`crossPen`、`penRight`、`penLeft`、`nearM`、`nearPen`、`movePen`、`orderPen`、`framePen`、`sideEdges`、`sideGap`、`lineGap`、`pad`、`base`、`margin`、`canvasW` |
| 功能區 | `side`(強制側別:`top`、`bottom`、`left`、`right`)、`ax`(同一框緣上起點位置之偏好,0～1)、`anchor: { edge, at }`(強制起點,`at` 0～1)、`tier`(強制層,0～3)、`x`(強制水平線左端)、`dx`(自動位置再位移)、`join`(接點之端:`l`、`r`、`auto`) |

- `style` 之顏色只收 `#rgb`、`#rrggbb` 與英文色名(不收 `rgb()` 等寫法);字型名稱不得含引號與 `<>&;\`.
- `layout` 之 `pad`(文字與水平線端點之距,預設 8)與 `find.pad`(框之外擴像素)同名不同義;`margin`(畫布留白)預設 16;`canvasW` 預設 0 為自動,指定時較窄者左右補白,超過者列問題 `CANVAS_TOO_WIDE`.其餘各鍵之意與預設見 §5 及 `WGuidechart.defaultLayout`.
- 調整原則:先改全域規則讓多數圖變好,再以功能區覆寫處理個案;覆寫寫上理由註解(例:「左欄疊有 4 框,上方最左之落點只容 1 個」).

## 9. 結果碼

**`issues`(問題)**:

| 碼 | 意義 |
|---|---|
| `BOX_TOO_CLOSE` | 框太近或相疊 |
| `LABEL_OVERLAP` | 標籤相疊 |
| `LEAD_THROUGH_LABEL` | 引線穿過他標籤 |
| `LEAD_CROSS` | 引線相交 |
| `LEAD_COVERS_TEXT` | 引線遮住其功能文字 |
| `LINE_OUT_OF_BAND` | 水平線超出層之範圍 |
| `NO_PATH` | 引線無可用之路徑(過於平躺或須穿入自身之框),以 `anchor`、`x`、`dx`、`side` 調整 |
| `TIER_OVERFLOW` | 某側 4 層仍排不下 |
| `CANVAS_TOO_WIDE` | 畫布寬超過層總寬(報告內之字級將小於他圖)或超過指定之 `canvasW` |

**`notes`(注意)**:`LEAD_THROUGH_BOX`(無法自動排入而穿框)、`TIER_NEAR`(該側改為靠近引線落點)、`FONT_FALLBACK`(設定之字型不在,字寬與繪製皆用替代字型;於有該字型之環境開啟 svg,字寬可能不同).

**reject 之錯誤碼**(`Error` 帶 `code`):

| 碼 | 意義 |
|---|---|
| `E_ARG` | 輸入無效(訊息只帶路徑索引,不回顯值) |
| `E_VIEW_NOT_FOUND` | `opt.names` 有不存在之圖名 |
| `E_BROWSER` | `launchBrowser` 失敗或回傳物件不合,或瀏覽器操作失敗 |
| `E_OPEN` | `open`、`openPage`、`afterCapture` 失敗,或視窗不固定,或截圖與視窗尺寸不同(`deviceScaleFactor` 須為 1) |
| `E_SETTLE` | 於 `capture.settleMs` 內畫面未穩定 |
| `E_BOX_NOT_FOUND` | 量不到框(含 `find.fn` 失敗、`union` 任一成員量不到) |
| `E_NOT_CAPTURED` | 該圖尚未取景,須加 `opt.capture` |
| `E_STALE` | 取景後 `find` 已變更,須重新取景 |
| `E_DATA` | 資料檔或截圖不合(截圖須可完整解碼且尺寸相符) |
| `E_CROP` | `crop` 超出截圖,或功能區落在裁切外 |
| `E_FS` | 建立資料夾或讀寫檔案失敗 |

已啟動之瀏覽器於成功與失敗時皆恰關閉一次.

## 11. 陷阱表

| 陷阱 | 對策 |
|---|---|
| 為了版面裁切截圖,圖放入報告後過小 | 全畫面為主,只有疊圖才裁 |
| 框切過漸層底之圖示 | 量框計入 `background-image` 之元素(`mode: 'fit'` 已計) |
| 相鄰兩框分開時框線壓到標題 | 合為一框,以「甲與乙」命名 |
| `mode: 'fit'` 對 canvas、按鈕本身等無子內容之元素量不到(`E_BOX_NOT_FOUND`,訊息提示改用 `box`) | 該功能區改 `mode: 'box'` |
| `union` 之一成員選擇器失效,以為會略過而仍出圖 | 任一成員量不到即 `E_BOX_NOT_FOUND`;修正該成員 |
| `find.fn` 引用外部變數,在頁面內找不到 | `fn` 須自足,所需值經 `find.arg` 傳入 |
| 取景時頁面仍在載入或動畫,截圖不穩 | 在 `open` 內等載完並停動畫;`E_SETTLE` 先查原因,不先加大 `settleMs` |
| 平分間距把功能區集中於一側之標籤推到遠端,引線無路可走 | 比較各種左右順序取總成本最低;仍無路則該側改靠近落點(注意 `TIER_NEAR`) |
| 只依各自最短引線排序,標籤順序與出發位置不符 | 順序依起點 x 由左往右 |
| 下方層之斜線遮住文字 | 依斜線角度估算避讓並加長水平線 |
| 過擠時找到第一組排得下之換向組合即停止比較,致引線穿框交錯 | 換 1～3 個之全部組合都比較,取兩層總成本最低者 |
| 引線貼著他框之邊緣走,看似穿框 | 30 像素內加罰 |
| 窄圖與寬圖混用,報告內字級不一 | 畫布寬一致 |
| 選填鍵寫錯(如顏色寫成 `rgb(...)`)而被靜默改用預設 | 開 `opt.debug`,看 `funLog('warn')` |
| 只改排版設定卻每次重新取景,或改了 `find` 卻沒重新取景(`E_STALE`) | 只改排版省略 `capture`;改 `find`、增刪功能區須 `capture: true` |
| 把圖名(中文)放進 `views[].name`,被拒收或成為檔名 | `name` 用安全檔名,圖名放使用端自有之鍵 |
| 以為套件會以離開碼 1 結束 | 套件不設離開碼;由使用端以 `res` 之 `issues` 自設 |
| 設定之字型不在,以替代字型量測與繪製(`FONT_FALLBACK`) | 在有該字型之機器產製,或確認替代字型可接受後才交付 |
| 只看自動檢核就交付 | 逐張原尺寸目視 |
