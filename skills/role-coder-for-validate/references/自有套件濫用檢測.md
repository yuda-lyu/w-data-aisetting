# 自有套件使用界線檢測（L0e）

**什麼是濫用**：讓自有套件（`wsemi` 與所有 `w-*`）在它的設計界線之外運作，而不是照介面用，或請套件擴充。

**為什麼要專門查**：套件的測試只保證「照介面用」時正確。濫用時功能照常、測試全綠，L0d 查得到選項也確實存在，所以 L0a–L5 都不會亮紅燈；問題要等到出事或被人問起才會發現。

## 1. 典型錯誤形狀（去識別）

某專案把「HTML 轉 PNG」從行程內呼叫搬成獨立 HTTP 服務，連鎖如下：

1. 套件的 `funPageWait` 是一個函式，原本直接傳入；搬成服務後，HTTP 的 JSON 傳不了函式。
2. 呼叫端用 `.toString()` 轉成字串傳過去。
3. 套件以 `isfun` 檢查參數，字串不會生效，於是服務端用 `new Function` 還原。

結果：

- **請求內容在主程序內被執行**：任何送得到請求者，都能以服務之權限讀寫檔案、執行程式。
- **這段完全沒有必要**：該函式只在瀏覽器內執行（Playwright 會再把它轉回字串送進瀏覽器），Node 端還原只為了通過 `isfun`；全專案只有 1 個呼叫端，內容固定 1 句，放在服務內即可。
- **同時發生之問題**：同一次改動順手開了 CORS `*`、註解掉只聽本機之設定，並把其他會執行程式碼之選項（`execJsHead`、`execJsPost`）也原樣透傳，而這些選項沒有任何呼叫端。

為什麼 3 個多月沒被發現：功能正常、測試全綠；提交訊息與此無關；弱掃工具未檢出；被注意到時，只評估「有只聽本機擋著」就放過，沒有人問「為什麼需要它」。

其他同類事例：自寫 `wmic` 查程序（Windows 11 已移除，查詢回空不報錯，回收從未生效）；瀏覽器端走公開 CDN 載入自有套件（停在舊版，舊版含已移除之元件而載入失敗）；為效能繞進元件之私有欄位（升版無聲失效）；關閉元件預設面板未核對需求（舊手冊載明之比例尺被關掉，數月無人察覺）。

## 2. 原則

1. **照介面用**：參數之型別與執行環境是契約。不湊出型別去通過檢查（字串還原成函式、物件假裝成陣列）。
2. **邊界只傳資料，不傳程式碼**：跨行程、跨網路只傳資料；要執行之判斷固定在執行端，至多傳白名單內之名稱。
3. **包成服務要重估信任**：套件假設呼叫端可信；包成 HTTP 後信任邊界變了。只開放呼叫端實際用到之資料參數，不原樣透傳選項；綁定位址、CORS、內容類型、驗證都要重新決定。
4. **只用公開介面**：不引用文件未載之內部模組，不讀元件之私有欄位。需要時請套件開放。
5. **套件不足就發 issue，不在使用端繞過**：不改 `node_modules`、不用副本或分叉、不自寫替代、不走公開 npm CDN（npmjs 之自有套件已停更，改用該套件自己的 gh-pages 或本機供檔）（全域設定 §5）。
6. **關閉預設功能要有依據**：關閉前核對需求與舊版文件，並就地註明理由或替代者。改版時最容易無聲弄丟原有需求。
7. **先問為何存在**：看到可疑寫法，先以 `git log -S` 查引入原因。不以「有防線」「功能正常」當不處理之理由。

## 3. 檢測方式

### 3.1 掃描

```bash
node <技能根>/scripts/audit-own-pkg.mjs --root <專案根> --info
```

只讀檔，不連外，不執行任何外部程式，無第三方依賴。自我測試：`node <技能根>/scripts/audit-own-pkg.selftest.mjs`（末行須為 `PASS n/n`）。

**掃描對象**：使用 `wsemi`、`w-*` 之專案（服務、應用、工具）。根目錄 `package.json` 之 `name` 本身是自有套件者視為「套件自身倉庫」：它就是 C2（程序與瀏覽器）、D1（對外界線）、E1（預設功能）所列功能之實作者，這三條不掃，其餘照掃。套件自身確有合法之動態執行（A1）者，於該列註明 `audit-own-pkg: allow <理由>`。

**不掃**：測試檔（`test/`、`tests/`、`spec/`、`test-*/`、`*.test.*`）、壓縮或打包檔（`*.min.*`、`*.umd.js`、單列逾 1000 字元）、`node_modules`、`dist`、`docs`、`tmp`、`bin-cache`、連結（symlink、junction）、被 `.gitignore` 排除者（含已被版控追蹤但符合 `.gitignore` 者）、單檔逾 3MB、非 mjs／cjs／js／ts／vue／html 之檔。略過數於第二行輸出。

| 規則 | 形狀 | 分級 | 對應原則 | 不算（誤報控制） |
|---|---|---|---|---|
| A1 | 動態執行字串：`new Function`、`Function(`、`eval(`、間接 eval、`vm.runIn*`、`vm.compileFunction` | 必修 | 1、2 | 字串與註解內之字樣、`$eval`、`new vm.Script`（只編譯） |
| A2 | 函式序列化：`funX.toString()`、`String(funX)` | 待判讀 | 2 | 一般數值之 `toString()` |
| A3 | 請求內容透傳至會執行之選項（`execJs*`、`scriptsHead`、`funPageWait`、`executablePath`、`cmd` 等；限同檔有 `request.payload`、`req.body` 等請求處理者） | 待判讀 | 3 | 程式內部選項（如 `funEvent`）、無請求處理之檔 |
| B1 | 引用套件內部模組：底線開頭之檔；巢狀路徑（如 `src/js/…`）而套件 `docs/` 無該檔文件頁（無 `docs/` 者標「無法核對」） | 待判讀 | 4 | `src/<單檔>`、`src/components/<元件>`、`dist/`、`test/tools/`、§4.3 已知公開路徑 |
| C1 | 自有套件走公開 npm CDN（jsDelivr `/npm/`、unpkg） | 待判讀 | 5 | 第三方套件、jsDelivr `/gh/`、`w-demores`（範例資源庫，暫維持 jsDelivr） |
| C2 | 自寫套件已有之功能：`wmic`、`taskkill`、`child.kill()`、`chromium.launch`、`puppeteer.launch` | 待判讀 | 5 | 套件自身倉庫、註解內之字樣 |
| C3 | 修補或改用副本：自有套件依賴為 `file:`、`link:`、`git+`、`npm:` 別名或路徑；`overrides`／`resolutions` 指向副本；`patch-package`；`patches/` 內自有套件之修補檔 | 必修 | 5 | 版號範圍、第三方套件、`overrides` 僅釘版號 |
| D1 | 服務對外界線：註解掉之 `host:`、`host: '0.0.0.0'`、`.listen(…, '0.0.0.0')`、CORS `*`、`cors: true` | 待判讀 | 3 | 套件自身倉庫、註解內之預設值說明 |
| E1 | 關閉地圖元件預設面板：`panel*` 內之 `show: false`（`--info` 才列） | 待判讀 | 6 | 非 `panel*` 之 `show: false`、未用 w-maplibregl-vue／w-leaflet-vue 者 |

判讀與使用：

- **必修**（A1、C3）修到 0。A1 確屬合法者，於同列或前一列註明 `audit-own-pkg: allow <理由>`（理由不可空，空者仍計必修並另列）；C3 無法行內註明，已確認合法者以 `--allow-pkg <套件名>` 列出，並於 `validate-own-pkg.md` 記理由。
- **掃描範圍要驗**：先看輸出前兩行。檔數為 0 離開碼 2（根目錄不存在、參數錯誤、`package.json` 無法解析亦為 2）；檔數明顯少於專案規模、或「引用自有套件」為 0 而專案確實用了自有套件，都代表範圍壞了，結果不算數。空結果不等於沒有問題。
- **待判讀**每條規則預設只列前 30 處，`--all` 列全部。
- **掃描只抓形狀**：通過不代表沒有濫用，§3.2 之三問與 §3.3 之查核仍要做。

### 3.2 待判讀逐項答三問

結果寫進 `./tmp/validate-own-pkg.md`，每項一列：站點／三問之答案／判定（合法、濫用、待請套件擴充）／處置。

1. **套件文件有寫這種用法嗎？**（README、JSDoc、範例頁）沒寫就是超出設計界線。
2. **這段為什麼存在？**（`git log -S`）解釋不了就當補丁，不原樣繼承。
3. **拿掉或改走公開介面會怎樣？** 能拿掉就拿掉；拿不掉的原因，就是要請套件擴充的內容。

### 3.3 掃描抓不到、要人工查的

- **函式或元件之私有欄位**：`$refs.x.map`、`vo._xxx`，對照套件文件之公開方法。
- **選項有宣告卻沒有呼叫端**：包成服務之 API，逐一 grep 呼叫端，沒有就刪。
- **同一套件兩份實例**：使用端引 `src`、另一套件引 `dist` 時，模組狀態各有一份（例：各開一個常駐瀏覽器）。確認是否預期。
- **經變數轉手之透傳**，以及路徑非字面值之 `import()`、`require()`：掃描只比對字面寫法。

### 4.3 公開介面與內部模組

自有套件皆未設 `exports`（抽查 7 個），深層路徑技術上載得到，是否公開只能靠文件判斷。自有套件發布時 `src/` 隨包，下游以 `src/<單檔>`、`src/components/<元件>`、`dist/`、`test/tools/` 取用為慣用方式，不算內部模組。

| 套件 | 應走 | 不應走 | 形狀 |
|---|---|---|---|
| wsemi | `wsemi/src/<函數>.mjs`（每函數一檔，各有文件頁；`getTrace.mjs` 為指定之共用入口） | 底線開頭之檔（`_trace.mjs`、`_execPortPids.mjs`） | 底線開頭即內部，不在公開索引 |
| w-component-vue | `src/js/` 之 `binarySearch`、`buildPopper`、`convertColor`、`createDetectDirective`、`createTransitionState`、`createVnodeEmitter`、`domDragDrop`、`domMutation`、`domResize`、`domStable`、`domVisible`、`parseDetectValue`（皆有文件頁）；`src/components/WAlert.mjs` | `src/js/` 其他檔（如 `parseSpace.mjs`，查無文件頁） | 以 `docs/` 有無該檔頁面為判準；已列者內建於掃描程式之 `B1_PUBLIC` |
| w-maplibregl-vue、w-leaflet-vue | 元件 prop 與公開方法（如 `getMapObject()`；README 與 JSDoc 無方法級說明，僅有範例頁） | 元件之 `map` 等私有欄位、`src/js/*` | 為效能繞過方法：應請套件提供輕量方法 |
| w-geo-vue | 元件 prop | `src/js/getSts.mjs`（檔案存在，README 與 `docs/` 無獨立頁，僅 prop 說明提及「可由 getSts 產生」） | 確認是否公開；是就請套件補文件 |

引用巢狀路徑時，已安裝套件若無 `docs/`（發布版不一定附），以該套件原始碼倉庫或其 gh-pages 之文件頁為準。

## 5. 命中濫用時的處置

依 §7 失敗處置，另加：

1. **追引入原因**：`git log -S '<關鍵字>'`，讀該提交之前的寫法。
2. **能刪就刪**：優先移除，其次改走公開介面，最後才是白名單。
3. **套件不足就發 issue**（全域設定 §5.2），不在使用端繞過。
