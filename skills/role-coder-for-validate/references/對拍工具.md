# 新舊版輸出對拍(L3)之工具:雜湊整個輸出樹、前進式假時鐘、記錄請求,與先驗工具本身

> 本檔為 SKILL.md Step 3 第 6 點之細則.下列程式之邏輯於 2026-11-19 在 Windows、Node v24.22.1 以夾具實跑(三種變異、固定／前進式時鐘之對照皆照所列結果;貼入本檔時僅精簡排版).記錄請求之作法(第 3 節末)為提案端作法,未另行實跑.

**觸發**:重構或資料處理改動要做前後輸出 diff(L3);審查他人之對拍工具或「0 處不同」之結論.

**為何**:對拍之價值全在工具之鑑別力.只比回傳值與幾個已知資料夾之工具,對[不該寫之檔也寫出]、[少寫一檔]、[請求之標頭不同]皆回[0 處不同],稿內卻寫成[比對全部產物、0 處不同].**典型錯誤形狀**:擬稿者之對拍工具只比回傳值與三個已知資料夾,稿內寫[比對全部產物、0 處不同];審查者植入[不該寫之檔也寫出]之變異,該工具仍判 0 處不同;另一案之工具不比請求之標頭.

## 1. 雜湊整個輸出樹

**檔名清單一項、每檔之內容一項**(必要時加每檔之修改時間):新增、消失、改動之檔都須使結果改變.

```js
import fs from 'node:fs'
import path from 'node:path'
import crypto from 'node:crypto'

let hashTree = (dir) => {
    let rels = []
    let walk = (d) => {
        for (let e of fs.readdirSync(d, { withFileTypes: true })) {
            let fp = path.join(d, e.name)
            e.isDirectory() ? walk(fp) : rels.push(path.relative(dir, fp).split(path.sep).join('/'))
        }
    }
    walk(dir)
    rels.sort()
    let h = (b) => crypto.createHash('sha256').update(b).digest('hex')
    let perFile = Object.fromEntries(rels.map((r) => [r, h(fs.readFileSync(path.join(dir, r)))]))
    return { names: h(rels.join('\n')), perFile, all: h(JSON.stringify(perFile)) }
}
// 判相同:a.all === b.all && a.names === b.names;不同時逐檔比 perFile 列出差異之檔
```

## 2. 採信[0 處不同]之前,先驗工具本身

以三種變異各產一份輸出樹,工具**都須判為不同**,否則工具不可用:

| 變異 | 實測(夾具:2 檔之輸出樹) |
|---|---|
| 同版再跑(對照,應相同) | 判為相同 |
| 多寫一檔 | 判為不同 |
| 少寫一檔 | 判為不同 |
| 改一個數字 | 判為不同 |
| (誤例)只比 `a.txt` 之工具對[多寫一檔] | 判為相同(漏網) |

稿內對比對範圍之敘述(比了哪些、沒比哪些)須與工具實際所比者一致.

## 3. 時間與外部請求

- **假時鐘以子類別取代 `Date`,含逐次前進式**:固定時鐘抓不到[成功路徑多取了一次現在],前進式(每讀一次前進固定量)抓得到.實測:舊版取一次、新版取兩次(以第二次之值輸出),固定時鐘下輸出相同(漏網),前進式時鐘下輸出不同(抓到).

```js
let RealDate = Date
let installClock = (mode) => {            // mode: 'fixed' | 'step'
    let t = RealDate.UTC(2026, 10, 19, 0, 0, 0)
    class FakeDate extends RealDate {
        constructor(...a) { a.length === 0 ? super(mode === 'step' ? (t += 1000) : t) : super(...a) }
        static now() { return mode === 'step' ? (t += 1000) : t }
    }
    globalThis.Date = FakeDate
}
// 還原:globalThis.Date = RealDate;新舊兩版各自在同一時鐘初值下重跑,再比輸出
```

- **對外請求者,另記錄請求之參數與標頭**(把 `fetch` 或 HTTP 客戶端包一層,依序記下 `{ method, url, headers, body }`,新舊兩版之記錄陣列逐筆比對):只比參數之工具會漏掉標頭之差異.

> §4 ~ §6 為使用端以多輪實際對拍歸納之作法與實例(2026-11),未於本庫另行實跑;§2 驗的是「工具」,下列驗的是「輸入、語料、正規化與夾具」——工具有鑑別力,輸入涵蓋不到改動之處仍會得到「0 處不同」.

## 4. 輸入須涵蓋改動,並以變異自證

1. **所植之變異須在該輸入下可觀察**:「修前修後輸出逐位相同」只在輸入觸及被改之處時才有意義.**典型錯誤形狀**:把「失敗時重抽 16 次」改為 15 次,而該輸入下連續失敗 16 次極少發生,輸出照舊逐位相同——不能當作比對有效之證據;改植於該輸入必經之分支(例:起點含某特殊值)才現出差異.
2. **被搬移或抽成共用之每一個分支,各植一個「改壞」之變異**:重構把邏輯抽成共用函數、呼叫端改呼叫它時,輸入須涵蓋被搬移之**每一個分支**(含「資源用盡即該筆從缺」之 `continue`、早退、預設值),對每個分支各植一個改壞之變異(例:拿掉該 `continue`),同時看**對拍**與**既有測試**有無轉紅.只驗其中幾個,不足以證明「搬移之每一處都等價」;存活者表示該分支於修前即無守門,記為缺口(補測試,或列已知不修並寫理由).
3. **盤點「被重構範圍內之既有變異」**,以變異之錨點對照**修前碼**之行號與範圍取交集;交集可為空集,不得默認非空.
4. **逐案比對之語料**(輸入集)須同時含:①既有測試內全部字串常值(以 AST 取,不以正規式——正規式漏模板字串、跳脫與串接)②規則生成之組合③由前兩者衍生之變形(大小寫、前後綴、拼接、分段).另植一批變異自證語料之鑑別力(實例:首輪植入 10 項,4 項未被發現,補語料後才 10 / 10).既定修正所致之差異,以**差異之形**歸類(還原舊值／只增項／逐段不同),不以字樣歸類.
5. **新增文字內部之守門**:以「還原新增之處再取雜湊」來守「其餘逐字不變」者,該雜湊不守新增文字之內部.新增之文字須另有**逐句有語意字句之斷言**,並各植一變異(語意反轉、刪句),以變異對**提案端原有之測試**實跑自證(實例:原測試以子字串斷言覆蓋新段約 7 成,補 10 項語意變異,於原測試全存活,補斷言後全殺).

## 5. 正規化須窄、須校準、須有負對照

新舊輸出含非決定性之處(耗時、時間戳、路徑)而須先正規化再比對時:

1. **只遮明確之記號**(如耗時 `\d+ ?ms|s|秒`、時間戳),不整行去數字:整行去數字會把同一行有意義之數字(計數、策略數)一併遮掉,獨立複審才發現.
2. **校準**:每情境每版本各跑 ≥ 3 次,證明被遮之處只有非決定性;**先以舊版跑兩次比對自己**(決定性之基準),再比新舊.
3. **結果檔以位元組層比對**(只刪明列之非決定性欄位),不經 JSON 往返——往返會抹掉 `-0` 與數字之寫法.
4. **負對照**:另植 ≥ 3 個(改壞結果、畫面、紀錄各一處),證明比對對各通道之差異皆偵得(實例:27 情境 × 2 版本 × 3 次,三處負對照各使 10 / 8 / 9 項轉紅);情境亦須含「預期不同」之負對照(同一份資料,設定取預設 vs 關閉)——只有全相同者,不證明比對有鑑別力.
5. **輸出之路徑與檔名,兩版須相同**:輸出含路徑或檔名(結果檔名、畫面印出之路徑)者,新舊兩版共用同一輸出路徑,不以版本夾名命名;輸出內之相對路徑統一換成佔位.**典型錯誤形狀**:以版本夾名命名結果檔,畫面印出之路徑不同,28 項只 1 項「相同」,誤認為大量差異.
6. **「整個輸出樹」另含專案根之檔案樹**:除各檔雜湊(§1)外,以專案根之檔案樹(相對路徑 + 內容雜湊,不含逐次覆寫者)為比對項;原只比結果檔、畫面、紀錄時,「多寫一檔」之變異抓不到.
7. **量含路徑之文字之位元組數**(任務書、提示詞、報告)時,新舊兩版**各以自己之根為工作目錄**:基準複本置於較深之路徑(如 `./tmp/…` 下)時,路徑較長使位元組虛增(實例:差 80,逐字比對才發現).

## 6. 夾具之情境

- 除「未觸發」之情境外,須含「**開啟 + 既有資料**」(升版後既有資料之處置).
- 合成之既有資料於夾具跑完一輪後,可能被被測程式重算覆蓋(例:派生之等級、資格判定);讀入新版前,須以被測物之 API 還原種子值——否則「合格之既有成品」之情境事實上為空(實例:未還原者無合格之既有成品,還原者每輪多一列「待補算之成品」).
- 新舊兩版之基準複本如何取得(換行、原位元組、接續輪之前一輪成果),見 skill[role-coder-for-test] 之 [references/pre-red-baseline.md](../../role-coder-for-test/references/pre-red-baseline.md).
