# 各家紀錄位置與查證表

> 本表是 [SKILL.md](../SKILL.md) §2 的逐項出處。核對日期 2026-11-03，環境 Windows 11；版本：Claude Code 2.1.317、Codex 0.166.0、OpenCode 1.19.5、agy 1.4.12。**版本一變即可能過時，動手前依 SKILL.md §3.1 重查。**

**狀態標記**

| 標記 | 意思 |
|---|---|
| 旗標實查 | 本機執行 `--help` 看到 |
| 官方文件 | 取自官方文件頁（頁名見各節） |

| 第三方 | 部落格、論壇、GitHub issue 等回報，未驗證 |

## 1. Claude Code

官方文件：`code.claude.com/docs/en/claude-directory`（「Application data」「Clear local data」）、`.../env-vars`。

| 項目 | 內容 | 狀態 |
|---|---|---|
| 對話紀錄 | `~/.claude/projects/<專案>/<session>.jsonl`；同名目錄下有 `subagents/`、`tool-results/`、`mcp-tasks/`。`<專案>` 為工作目錄路徑把非英數字元換成 `-` | 官方文件＋本機觀察 |
| 會被年齡掃除的其他路徑 | `file-history/<session>/`（只留最近 100 個檢查點）、`plans/`、`debug/`（僅開 debug 時寫入）、`paste-cache/`、`image-cache/`、`uploads/`、`session-env/`、`tasks/`、`backups/`（留最新 5 份）等；`shell-snapshots/` 正常結束即移除 | 官方文件 |
| 不被年齡掃除 | `history.jsonl`（提示詞歷史，HIPAA 設定例外）、`stats-cache.json`、`projects/<專案>/memory/`（auto memory）、`sessions/`（每個執行中 session 一小檔，結束即移除） | 官方文件 |
| `cleanupPeriodDays` | 預設 30，最小 1，設 `0` 會驗證失敗；`claude -p --bare` 不執行掃除；無法確定保留期時暫停掃除。Claude Desktop／Cowork 的 transcripts 另受 `desktopSessionCleanupPeriodDays` 管（v2.1.248 起） | 官方文件 |
| 本機未見者 | `history.jsonl`、`debug/`、`paste-cache/`、`tasks/`、`plans/` 在核對的那台不存在；`.last-cleanup`（小檔）存在，官方頁未載，用途未查證 | 本機觀察 |
| 不落紀錄（旗標） | `--no-session-persistence`：「sessions will not be saved to disk and cannot be resumed (only works with --print)」 | 旗標實查 |
| 不落紀錄（環境變數） | `CLAUDE_CODE_SKIP_PROMPT_HISTORY=1`：跳過寫入 prompt history 與 session transcripts，該 session 不出現在 `--resume`、`--continue`、上鍵歷史；claude-directory 頁稱「in any mode」 | 官方文件 |
| 手動清除 | `claude purge [路徑] [--all] [--dry-run] [-i] [-y]`；v2.1.288 前名為 `claude project purge`。刪：該專案 `projects/` 下的 transcripts 與 auto memory、`tasks/`／`debug/`／`file-history/` 的對應項、`history.jsonl` 的相符行、`~/.claude.json` 的專案項。不碰 `shell-snapshots/`、`backups/` 與暫存區的圖片、scratchpad；`--all` 連 `history.jsonl` 整檔刪。執行前印清單並要求確認 | 旗標實查＋官方文件 |
| 官方列的「須保留」 | `.credentials.json`、`agent-memory/`、`jobs/`、`daemon/`；另 `~/.claude.json`、`settings.json`、`plugins/` 不可刪 | 官方文件 |

**刪除代價**（官方文件「Clear local data」表）

| 刪 | 失去 |
|---|---|
| `projects/` | 過去 session 的 resume、continue、rewind，以及所有專案的 auto memory |
| `history.jsonl` | 上鍵提示詞回溯、`Ctrl+R` 搜尋、`!` 指令補全 |
| `file-history/` | 過去 session 的檢查點還原 |
| `paste-cache/` | 回溯提示詞中的大段貼上內容 |
| `debug/`、`plans/`、`session-env/`、`shell-snapshots/`、`backups/` | 無使用者可見的損失 |

## 2. Codex

官方文件：OpenAI Codex CLI 參考頁（`developers.openai.com/codex/cli/reference`，會導向官方開發者文件站）。

| 項目 | 內容 | 狀態 |
|---|---|---|
| 對話紀錄 | `~/.codex/sessions/<年>/<月>/<日>/rollout-*.jsonl`（年／月／日分層為本機所見；官方頁僅稱 rollout files） | 本機觀察 |
| 其他大檔 | `logs_*.sqlite`、`state_*.sqlite`、`thread_history_*.sqlite`（檔名尾數隨版本變）、`cache/`、`.tmp/` | 本機觀察 |
| 內建保留 | **未查到**：官方頁只描述手動 archive、delete，無保留期或自動刪除；第三方文章亦未見 | 官方文件（缺漏）＋第三方 |
| 不落紀錄 | `codex exec --ephemeral`：「Run without persisting session files to disk」 | 旗標實查＋官方文件 |

| `codex archive <id或名稱>` | 從 session 清單隱藏，**不刪 transcript**；第三方亦稱 JSONL 仍留在磁碟 | 官方文件＋第三方 |
| `codex delete <id或名稱>` | 永久刪除單一 session；`--force` 時引數須為 UUID，具名者仍須確認 | 旗標實查＋官方文件 |
| 直接刪目錄的風險 | 第三方稱 rollout 被手刪後，索引中的 thread 會成孤兒，建議用 `codex delete` | 第三方（未驗證） |
| 憑證與設定 | `auth.json`、`config.toml`（不可刪） | 本機觀察 |

## 3. OpenCode

官方文件：`opencode.ai/docs/config`。

| 項目 | 內容 | 狀態 |
|---|---|---|
| 資料庫 | 單一 sqlite，位置以 `opencode db path` 為準；執行中另有 `-wal`、`-shm` | 旗標實查 |
| 其他 | `log/opencode.log`（單檔、未見輪替）、`snapshot/`、`tool-output/` | 本機觀察 |
| 內建保留 | 官方設定頁**無** session 保留或自動刪除設定。本機日誌有 `message=cleanup prune=7.days` 行，但其刪除對象與是否縮檔**未查證**；GitHub issue 稱「no retention policy, no size cap」 | 官方文件（缺漏）＋本機觀察＋第三方 |
| 易混淆 | 設定鍵 `compaction.prune`（預設 `false`）是「移除舊工具輸出以省 token」，與刪除本機紀錄無關 | 官方文件 |
| 快照 | `"snapshot": false` 可關閉快照，代價是 agent 的改動不能經 UI 回復 | 官方文件 |
| 不落紀錄 | **無**：`opencode run --help` 無 ephemeral 或 no-persist 類旗標（有 `-c`、`-s`、`--fork`、`--title`） | 旗標實查 |
| 刪除 | `opencode session delete <sessionID>`、`opencode db [query]`（可跑 SQL） | 旗標實查 |
| 刪列不縮檔 | `session delete` 只刪列、檔案不縮，需 `VACUUM`；需關閉所有 opencode 行程並留足暫存空間 | 第三方（GitHub issue）；VACUUM 為 sqlite 標準行為，本機未實跑 |
