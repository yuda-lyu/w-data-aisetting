# 計算方法之調研與驗證：定義、算法、實作分開驗

## 0. 一分鐘看懂

**什麼時候用**：要回答「這個計算對不對」「該用哪個方法」「換成那樣會不會比較好」時。計算方法之錯誤多半不在常見輸入出現，而在退化配置、邊界、尺度改變時出現；只用手邊之真實資料跑一遍，通常測不到。

**要交出什麼**（放 `./tmp/<案名>/`）：

| 檔 | 內容 |
|---|---|
| `calc-layers.md` | 三層表：被計算之量之定義、候選演算法（含出處與已知缺陷）、實作（套件、版本、`檔:行`） |
| `calc-robust.md` | 數值穩健性盤點（Step 3） |
| 參考解與驗證腳本、log | Step 4～6 |
| `calc-report.md` | 對抗案例表與實測結果、真實資料分類統計、自我檢查之必要／充分分析、領域適用性結論、效能結論（有做才有）、建議與影響範圍 |

任務結束時 `./tmp/` 依全域設定清除；報告與腳本要留給第三者複驗者，移到使用者指定之位置（專案 docs 目錄，或隨回報附上）並說明。

**什麼叫完成**：參考解已以不變量驗過，並與第二種獨立算法互證（做不到者寫明原因）；對抗案例逐類有結果（最大差、非有限數之點數、例外數），表上每格為已證、刻意不測（附理由）、已知不修（附理由）三者之一，無空白格；真實資料之偏差已逐點分類成因；建議之方法在對抗案例與真實資料上都通過；結論寫明未測之情形。

## 1. 三條鐵則

1. **定義、演算法、實作三層分開**。例：自然鄰點內插之 Sibson 權重 w_i = a_i ／ Σa_j 是定義，a_i 為「把查詢點 x 插入後 x 之新 Voronoi 區塊 V(x)」與「原資料點集中第 i 點之 Voronoi 區塊 V(x_i)」之重疊面積，Σa_j 即 V(x) 之面積（Liang & Hale 2010，§2.2 式 (1)）。求 a_i 之演算法不只一種，數值性質不同：Watson–Sambridge（亦稱 compound signed decomposition，下稱有號分解）以外心為頂點之有號三角形面積相加減，查詢點靠近三角網之邊時相減之兩數極大而發生大數相消；Braun–Sambridge、Boissonnat–Cazals、Hiyoshi 與 Liang & Hale 等為避免相消之其他算法（同論文 §3、§4）；離散 Sibson（Park et al. 2006）則是不顯式算面積之另一類。某套件某版本之程式是實作，可能另有其自己之缺陷。比較或推薦時寫清楚是哪一層，不可因同屬一個定義而把不同演算法當成同一種。
2. **隨機抽樣全對不等於正確**。真實資料之隨機位置幾乎碰不到退化配置；退化案例要刻意構造、逐類實測。
3. **「較準」「較合理」要量測**。以精確解比對或交叉驗證量出差異與信賴區間；理論上較正確之作法，在資料上不一定量得出差別，量不出時不以「更準」為由改動。

## 2. 步驟

### Step 1 三層表（`calc-layers.md`）

- **定義**：寫出被計算之量之數學定義與定義域（例：Sibson 權重只在資料凸包內有定義，凸包外重疊多邊形無界、a_i 無限大，Liang & Hale 2010 §2.2；分母為零時無定義）。
- **演算法**：列候選，每個附一手出處（依 skill[role-researcher-for-validate]，來源記入其 `research-sources.md`）、精度、穩健性、複雜度、適用域。
- **實作**：使用中之套件與版本、關鍵 `檔:行`；與定義或演算法不一致之處逐條列出。實作屬自有套件（wsemi、w-*）者，缺陷依全域設定 §5.2 發 issue，使用界線依 skill[role-coder-for-validate] L0e，不在使用端自寫替代。

### Step 2 演算法譜系

對每個候選查：原始方法 → 已被指出之缺陷 → 後繼改良。官方文件中之警語（「inaccurate」「unstable」「not robust」）、論文之相關研究段落與上游原始碼之註解優先讀；改良者之論文通常說明前者錯在哪、在什麼條件下錯。推薦已知有缺陷之演算法者，寫明理由。

### Step 3 讀碼盤點數值穩健性（`calc-robust.md`）

逐項找出並記 `檔:行`：

| 項 | 看什麼 |
|---|---|
| 絕對容許值 | 寫死之容許值（如 1e-9 一類），單位為何、是否隨資料尺度；正規化或換單位後，是否把正常之小三角形、小區塊誤判為退化 |
| 大數相消 | 兩個大數相減、接近零之分母、外心或交點在極遠處（外心公式遇近共線之三點，圓心距離隨偏離量之倒數增大，實算見 Step 5） |
| 退化分支 | 被判為退化時怎麼處理：丟到遠點、改用近似、略過 |
| 被吞之例外 | `catch` 後給預設值（0、平分、沿用）而不告知 |
| NaN 與無限大 | 是否會被吞成有限值：JavaScript 之 `x \|\| 0` 把 NaN 吞成 0（`x ?? 0` 不會）；累加寫成 `(acc \|\| 0) + x` 時，先前之 NaN 被歸零後繼續累加，得到有限而錯誤之值；比較式 `x > tol` 遇 NaN 為 false 而放行（以上為 JavaScript 實測，依 IEEE 754 之比較規則；他種語言依其比較規則查證） |
| 正規化（除以總和） | 除後總和恆為 1（各分量為有限數時），對有限而錯誤之分量亦成立，所以「和為 1」攔不到這類錯誤；要比對的是除之前之總量與獨立算出之總量（Sibson 權重：Σa_j 對 V(x) 之面積） |
| 外框、裁切、截斷 | 為了使量有界而加之人為邊界，會否改變定義域內之結果：外框小於查詢點加入後之新區塊範圍時，該區塊被裁掉，靠近邊界之查詢點之值隨之改變 |
| 前處理 | 正規化、投影、去重之目的與副作用 |

### Step 4 獨立參考解

- 用有理數（BigInt）精確計算、高精度，或第二種獨立演算法。
- **先驗參考解本身**：以不變量檢查——一次函數重現、權重和為 1、各部分面積和等於總面積、對稱、平移與等比縮放不變、與已知解析解比對。這些都只是必要條件，通過只證明參考解沒有明顯錯誤；所以參考解須與第二種彼此獨立之算法互相比對，做不到者寫明原因，並把參考解之可信度降一級。
- 範例（Sibson 權重，已實算）：以半平面裁切直接求 V(x) ∩ V(x_i)（不經三角網與外心），所得權重和為 1、Σa_j 等於 V(x) 之面積、Σw_i·x_i 等於 x、對一次函數之內插值等於真值，平移加等比縮放後權重之最大差在 1e-12 以內。

### Step 5 對抗案例

依演算法類別列出退化點並逐一實測，每案記：與參考解之最大差、非有限數之點數、例外數。表上每格為已證、刻意不測（附理由）、已知不修（附理由）三者之一。

| 類別 | 必測 |
|---|---|
| 計算幾何 | 恰在邊上或頂點上；共線；共圓或共球；重複點；極近之點群；極扁或極小之三角形；查詢點與三角網邊之距離 h 由大到小逼近 0（如 1e-2 至接近機器精度）；規則格點與其細化（格距減半時，新增之查詢點即邊中點與格心；6×6 格點實算，新增點全部恰在三角網之邊上）；旋轉或斜向之格點；極大座標值；全部共線；點數不足 |
| 數值計算 | 0、負數、極大極小、溢位與下溢、空輸入、NaN 輸入、病態矩陣 |
| 統計估計 | 樣本極少、全部相同、離群值、權重為 0 |
| 座標與單位 | 跨越投影帶或經線、高緯、單位混用 |

實算參照（外心公式，三點為 (0,0)、(1,0) 與 (0.5,h)）：h = 1e-3、1e-6、1e-9、1e-12 時，圓心之 y 座標約為 −1.25e2、−1.25e5、−1.25e8、−1.25e11；h = 0（三點共線）時分母為 0，以含除以行列式之外心公式計算得 NaN 與 −Infinity（實作若對過大之圓另設判斷，結果依其設計，須讀碼確認）。

### Step 6 真實資料

- 可全數就全數，否則分層抽樣並推估母體（附標準誤）。
- 與參考解比對；**偏差逐點分類成因**，對照組要能把各機制分開（例：同時算「有人為外框」與「無外框」兩種參考解）。不把總偏差歸給單一機制，先分類再加總。
- 新方法在全部抽樣上之最大差、超過容許值之點數。

### Step 7 自我檢查與偵測

- 每個檢查寫明是必要條件還是充分條件、攔不到哪些錯。例（Sibson 權重，已實算）：①和為 1 因除以 Σa_j 而恆成立，對有限而錯誤之 a_i 亦成立，不能用來發現這類錯誤；②局部座標性質 Σw_i·x_i = x（等同對一次函數之內插重現，因為兩者都只要求和為 1 與 Σw_i·x_i = x）是必要條件：鄰點數 k 大於 3 時，這三條件（二維：和為 1 一條、兩個座標各一條）留有 k−3 個自由度，另一組與正確權重不同之權重也能同時滿足（實算 k = 6 之例已構造出）。這兩項檢查是否攔得到鄰點集合判錯、面積算錯，逐一回答，答不出者標「攔不到」。
- 門檻用相對於局部尺度之量，不用帶單位之絕對值。
- 判斷式寫成 `!(dev <= tol)`，使 NaN 被攔下（NaN 與任何數比較皆為 false，故 `!(NaN <= tol)` 為 true；JavaScript 實測）；輸出前檢查全部為有限數（`Number.isFinite`）。
- 檢查不過時不得靜默輸出：改走備援算法，或回 null 並告知原因。

### Step 8 領域適用性

- **座標與單位**：球面近似下，同一緯度圈上經差 1° 之距離是緯差 1° 之距離之 cos(緯度) 倍，所以把經緯度（度）直接當等距平面座標時，東西向相對南北向被放大 1/cos(緯度) 倍（緯度 45° 約 1.41、60° 為 2.0、75° 約 3.86；以橢球計算時，緯度 0°～75° 間與 1/cos 之差小於 0.7%，實算）。改用適合研究區之投影座標後，兩向尺度較接近，但投影本身亦有尺度失真，須查所選投影在研究區之尺度因子；是否因此較準仍要量測（本節末）。
- **定義域外**：列出可行之處理（不給值、投影至邊界、虛擬點、改用全域方法、最近點），比較其連續性、依據之資料量與人為參數；人為外框會連帶改變定義域內靠邊之值（Step 3）。
- **領域規範**：主管機關或業界標準是否指定方法、參數、單位。
- **是否較合理**：以留一交叉驗證（拿掉一點、用其餘估它）比較方案，做配對比較（同一批被拿掉之點，兩方案之誤差相減）並附 bootstrap 信賴區間；區間含 0 只表示在該信賴水準下判不出差別，不證明沒有差別，量不出時不以「更合理」為由改動。

### Step 9 效能

先量各段耗時再談加速：整體流程之時間若在下游，就寫明加速對整體之影響有限；分段計時後逐段檢查有無每次查詢都重建之資料結構（如三角網、空間索引）。效能結論寫入 `calc-report.md`。

### Step 10 影響範圍

- 新舊輸出以容許值比對（換演算法後末位不同是常態），統計超過容許值之筆數。
- 下游若依結果做離散選擇（取最大者、分類門檻），檢查末位差異會否改變選擇。
- 據此估重算範圍與下游重跑之成本。

## 3. 典型錯誤形狀

- **推薦已知失準之演算法**：調研時把有號分解（大數相消）與其後之穩定算法當成同一種算法，推薦了前者；前者在查詢點靠近三角網內部邊時大數相消，恰在邊上時外心無定義，可能得 NaN 或無限大。把規則格點之資料內插到格距減半之格點時，新增之查詢點全數恰在邊上，正好落在這個弱點。
- **NaN 被吞成錯值**：累加寫成 `(acc.get(k) || 0) + term`，NaN 被歸零後繼續累加，得到有限而錯誤之值；檢查式 `dev > tol` 對 NaN 為 false，未攔下。
- **抽樣全對就宣稱正確**：在真實資料之隨機位置抽樣，與參考解全符，即據以推薦；換成對抗案例才發現缺陷。
- **總偏差歸一因**：以單一參考解比對得總偏差，全歸給一個機制；逐點分類後，主要來自另一個機制（人為外框裁切），另一部分來自第三方函式庫之寫死絕對門檻，把正規化後之小三角形當成退化。據原結論規劃之修正只涵蓋其中一個機制。
- **必要條件當充分條件**：以局部座標性質檢查權重，鄰點數大於 3 時權重錯了仍可通過。
- **假定「理論上較正確」就較準**：改用投影座標雖在幾何上較正確，但留一交叉驗證若顯示兩方案誤差之配對差異，其信賴區間含 0，則改了只會使全部結果改變而無可證之效益；先量測再決定。

| dispatch-* | 派獨立複審或另一模型實作參考解時之派工、權限與逾時 |
