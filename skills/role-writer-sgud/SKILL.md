# role-writer-sgud — 專案／套件之指引要求文件(sgud)

本技能由全域設定抽出(2026-11-10,原全域 §14 與 §12.2 之落檔格式).全域設定只留觸發、配置、「先讀 state.md」與版控之鐵則,細節在此.

**why**:程式碼是強約束的檢查與執行軌跡,提示詞是弱約束的原則與要點;指引要求類文字集中於固定位置並納入版控,才能追蹤其演變、避免散落與重複讀取浪費 token.

## 1. 配置

專案/套件根目錄之 `CLAUDE.md`(進入點,自動載入)＋ `./sgud/`:

| 類 | 檔 | 內容 |
|---|---|---|
| 經驗 | `sgud/exp/experience.md` | 執行時之累積經驗,留給後續嘗試、執行、判斷 |
| 處理要點 | `sgud/proc/process.md` | 業務端之特化要求與其處理流程 |
| 規則帳本 | `sgud/rule/rulebook.md` | **藍圖**:以規則為單位記程式碼須長成什麼樣,附盤點指令、站點全集與判準,或由規格產出之測試清單 |
| 狀態 | `sgud/state/state.md` | **現況**:當前已開發功能之最新狀態(各功能做到哪裡、對應之規則帳本條目與測試檔、已知缺口與待辦、最近一次驗證或發布之版本);與規則帳本比對即知尚未做到者 |
| 回饋 | `sgud/feedback/feedback.md` | 任務中發現之自有套件、全域技能、全域設定之調整與抽提提案(§5);只增不改,處置結果另記一列,供主控核實、盤點與整合 |

## 2. 讀與寫

- **接續工作先讀 `state.md`**,不必翻經驗檔;完成一項功能或結束一輪工作時即更新 `state.md`.**只記現況、不寫過程**(過程寫入經驗).
- 規則帳本列為規則者(含狀態為未做/部分)是未完成之預期功能,不是死碼;判定死碼前先比對(細則見 skill[role-coder-for-validate] Step 2).
- **舊制對應**:根目錄之 `CLAUDE_experience.md`、`CLAUDE_process.md`、`CLAUDE_rulebook.md`、`CLAUDE_state.md` 依序對應 §1 表之前四檔.遇舊制者照其現有位置讀寫,不自行遷移;遷移由該專案之主控或使用者安排(自有套件由 opensrcOper 主控於該套件下次更新時遷移).

## 3. 過長即整理

判準:不好找、或整份讀入太浪費 token;約 30KB 以上即應考慮.

- 經驗:把舊經驗抽出為 `experience_<年月日>.md`,`experience.md` 註明何時抽出至哪檔;需要久遠經驗時再調閱.
- 處理要點、規則帳本:依類型拆為 `process_<類型>.md`、`rulebook_<類型>.md`(類型依專案自訂),主檔只留「哪類查哪檔」之索引.
- 狀態:依功能類型拆為 `state_<類型>.md`,`state.md` 只留索引.
- 整理時節號與標題不變,既有引用才對得上;不刪內容,只搬移.

## 4. 版控與發布

- **只有 `sgud/` 納入 git 版控**;`CLAUDE.md`(給 agent 之進入點)與 `CLAUDE_settings.md` 等 `CLAUDE*.md` **維持不入版控**——`.gitignore` 保留 `CLAUDE*.md`,**不得加 `!CLAUDE.md`**,也不得排除 `sgud`.
- `sgud/` 與程式碼同為資產,**隨 npm 包發布**;`.npmignore` 預設不提供(npm 依 `.gitignore`,`CLAUDE*.md` 自然不入包),只在須排除外部執行檔、或單一資料夾 ≥10MB 且使用端用不到之非程式碼資料時才提供——此時首段須完整抄錄 `.gitignore`(npm 有 `.npmignore` 即不讀 `.gitignore`),再逐條加排除項並註明理由.
- repo 為公開庫時,`sgud/` 內容不得含金鑰、權杖、內網位址或帳號資訊,亦不寫使用端專案之名稱與案情.

## 5. 回饋之落檔(全域 §12.2)

- 任務(或一輪派工)結束、交付報告之前,回顧三類:自有套件、全域技能、全域設定(判準見全域 §12.2).
- **有則先落檔、再回報**:寫入本次工作所在之套件或專案之 `sgud/feedback/feedback.md`,一條一列,欄位:日期、類別〔自有套件/全域技能/全域設定〕、對象、內容、依據〔`檔:行`、指令輸出或事件〕;再於回報中列〈回饋〉一節(置於[需你決定]之前).無則回報寫[回饋:無].
- 只增不改:處置結果(已通報、已修、不採納)另記一列,寫明承接哪一列.
- 回饋是紀錄與提案,不等於自行修改:自有套件與全域技能、全域設定之實際修改仍走全域 §5.2、§13 之通報管道.
- 公開庫之 `sgud/feedback/` 同 §4 之限制.
