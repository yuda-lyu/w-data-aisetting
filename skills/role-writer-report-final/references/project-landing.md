# 落地到專案

本技能只給預設與判斷方法。要長期維護一份整體成果類報告，專案須把裁定沉澱成自己的要點與檢查，否則每輪都會重犯。下列是建議之結構，名稱可依專案調整。**專案已有者照其現況，不重建。**

**適用前提**：第 1～6 節（文件堆疊、內容分層、產線、內建檢查、lint）針對需長期維護、多期產製之報告。單次、手寫之報告可只採第 7 節（新裁定之沉澱）與第 10 節（自他案借用），其餘降為選用；專案有凍結或限制新增檔案之規定者，先問裁定者，不自行新增產線檔案。要點之位置與體例依專案規定（本技能不指定檔名）。

## 1. 文件堆疊

```
事實層       共用資料檔、機器衍生數據（提交紀錄、掃描結果、標準圖）、功能要點與流程規格
全系列要點   撰寫要點（含禁詞與裁決對照表）、產圖要點、產製架構要點
系列要點     成果類報告之定位、與其他系列之差異、共通判準
單報告規格   撰寫原則與範例（章節、逐條裁定、亮點清單、定稿句、檢核清單、版本紀錄）
產製程式     圖清單、產圖、產文、轉檔、總入口
檢核         lint、產製時內建檢查、候選掃描、人工驗證
```

**衝突時**：專屬規定優先於通則，同一事項以日期較新之裁定為準。原則文件依時序累積時，早期例句會被取代，於檔首說明。

## 2. 內容類型分層

| 類型 | 定義 | 真理載體 | 治理規則 |
|---|---|---|---|
| 識別事實 | 委託單位、執行廠商、案名與簡稱 | 共用資料檔 | 產製程式不硬編 |
| 清單事實 | 全案須一致之結構化清單（系統組成） | 共用資料檔 | 異動後依消費對照重產 |
| 機器衍生數據 | 由程式或執行結果產生 | 各自之產出檔 | 絕不手寫；來源不存在即報錯；統計只在階段性彙整時更新 |
| 定稿句 | 裁定者逐字裁定之句 | 產製程式加註記、原則文件登記 | 不得改動，兩處同步 |
| 章節本文 | 實打實撰寫之敘述 | 各報告之產文程式 | 受要點約束 |
| 圖 | 標準圖、自繪圖、官方圖、亮點展示圖 | 各自之來源 | 依〈產圖規範〉與〈亮點與配圖〉 |
| 裁決與禁令 | 禁詞、用語、正名 | 裁決對照表 | 新裁決先入表，lint 同步 |

**報告 md 與 docx 是純產物**，任何手改都會消失。

**共用資料檔之准入**：同一事實出現於兩份以上報告、或裁定全案一致之結構化事實才進；單報告專屬敘述、成段文字、語氣變體不進。登記欄位與消費報告之對照，異動時據以決定重產範圍。

## 3. 產線

每份報告之產線依下列分工，各為獨立之程式或模組（檔名與目錄結構由專案決定）：

| 分工 | 內容 |
|---|---|
| 圖清單 | 每張圖之來源、目標檔名與圖名；產圖與產文共用同一份 |
| 圖數據 | 有自繪圖者，每張一份，與繪圖引擎無關 |
| 產圖 | 依清單複製或繪製，印出尺寸與寬高比 |
| 產文 | 正文之唯一載體，內建檢查見第 4 節 |
| 轉檔 | 接共用之 md 轉 docx 模組（依 skill[role-writer-report-convert-to-docx]） |
| 總入口 | 依序執行以上各步 |

md、docx 與圖皆為產物，另放於報告之輸出夾。輸出與暫存之路徑依專案與全域之路徑規範；專案若分案或分期維護多套報告，依其約定決定是否共用工具；要各自獨立者不互相 import。

## 4. 產文時內建檢查（不符即中止）

可機械判定且會反覆犯者，寫進產文程式：

- 圖：每張先引用後放置、各放置 1 次、清單無未用之圖、圖名不重複且末字為「圖」、圖檔存在。
- 系統清單：各節與共用資料之系統全集一致，不重複、不遺漏。
- 文體：落單之一句話（判準依〈文句與段落診斷〉第 5 節，不以句數，例外須可放行；字數門檻由專案自訂）、條列超長、條列後接圖、粗體小標、引圖句未收尾（引圖短語後同句之圖內說明可放行）。檢查與裁定者之段落分工衝突時，改檢查。
- 附錄（以專案實際有之文件為準）：每份皆提及、編號存在、有分冊之系統提出其分冊、同段依脈絡排序、次要附錄未細述、操作與測試皆有者成對。
- 範本：沿用段落之占位符皆已代入。

## 5. lint

lint 之通用方法在 skill[role-writer-validate] 之《文句與因果審閱》§2，本節只列落地於專案時之結構：

- **只收有固定字面者**，語意判斷靠掃描與通讀。
- **規則與裁決表一一對應**：每條帶編號，以程式自動核對「表有而 lint 缺」「lint 有而表缺」，新增時同步。
- **禁詞之單一來源**：缺陷詞、地區用語等詞表獨立成檔，多處引用。
- **圖內文字同一份規則**：圖數據與圖之 HTML 文字套用同一份 lint，版式類規則除外。
- **掃描範圍**：產出之 md 為主，規則文件與舊版產線不掃；新報告須納入。
- **系列限定**：成果章專屬之規則（防禦句、小標、期程）限定於成果類報告。

## 6. 候選掃描

候選掃描之判準表、共通規則、換詞連用之處理與附帶之掃描程式，都在 skill[role-writer-validate] 之《文句與因果審閱》§3、§10；本技能不另存判準表。**是否建立專案自己之掃描器、如何調校由專案決定**；未建者，有固定字面者以搜尋近似，其餘靠逐段通讀（依 skill[role-writer-validate] Step 3b）。判準要依專案之報告調校，並去掉專案名詞（系統名、章號）後才能移用。

## 7. 新裁定之沉澱

| 裁定類型 | 同步到 |
|---|---|
| 全系列之用字或文句 | 裁決表與要點相關節 → lint（可機械判定者）→ 同型全掃；表、lint、要點三處一致 |
| 成果類專屬之逐句原則 | 單報告規格之新條、檢核項與版本紀錄；可判定者加 lint 或產文檢查；多份同改 |
| 定位、框架、流程、不提及範圍 | 系列要點與單報告規格 |
| 逐字裁定之句 | 產文程式之定稿註記與單報告規格之登記處 |
| 全域技能本身有誤 | 依全域設定之通報管道 |

**記法**（預設；專案之要點有固定體例者依其體例）：裁定者之指示、問題之分析、通則、改前改後、影響範圍。理由要留，否則日後判斷不了例外。

## 8. 派工

委派子代理撰寫或修改時，提示須含：

1. 任務範圍（哪份、哪些章節、新寫或修訂）。
2. 閱讀清單（整篇讀畢再動工）。
3. 事實摘錄，明令不硬編、不自創；沒有資料之層級不寫。
4. 定稿句清單，一字不改。
5. 禁詞表，改功能敘述前先查證。
6. 輸出約定（改來源、同步範例、暫存位置、不同時轉檔〔依 skill[role-writer-report-convert-to-docx]〕）。
7. 驗收標準（lint、定稿句逐字比對、主代理審查）。

判準：無對話記憶之 agent 依此第一次即產出合規內容。子代理之回報仍須抽驗；審閱與核對類之派工範本（逐句審閱、逐字校對、事實核對）見 skill[role-writer-validate] 之《派工範本》§5～§7，派工方法依 skill[dispatch-claude]、skill[dispatch-codex]、skill[dispatch-opencode]。

## 9. 新期別之接入

1. 確認期別與案別，建報告夾。
2. 以前一期之產線為底，改期別相關常數（名稱、年度、前一年度、章次、版次）。
3. 依〈素材提取與事實核對〉提取與歸類，對照前一期判斷新進度。
4. 先定亮點與圖清單，再寫正文，小結最後寫。
5. 產圖 → 產文 → lint → 審定 → 產 docx → 表格核對。

有必須沿用之段落者（專案參數第 22 項），其年度由程式代入；段落內容只在委託單位有更新時才改。

## 10. 自其他專案借用原則

專案之間可互相參考，但不得整包照搬。逐條判定並留下對照表：

| 判定 | 作法 |
|---|---|
| 沿用 | 原則照收，名稱與案例改抽象或本專案之寫法 |
| 改寫 | 收其通則，內容或範圍依本專案改寫，說明如何改 |
| 不適用 | 來源專案專屬或本專案無對應之事實，不收並寫理由 |
| 待裁定 | 既有原則判不了者不收，列明為何判不了，待裁定 |

- 判定之問句：此規則之事實前提在本專案成立嗎？
- 殷鑑改抽象，不杜撰本專案之殷鑑。
- 範本、程式與資料不跨案共用，文件屬性會帶入他案資訊；範本之檢查與清理依 skill[role-writer-report-convert-to-docx] 第 4 節。
- 裁定日期與來源保留於專案文件，便於追溯。
