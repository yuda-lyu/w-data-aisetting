# 格式、標點與用字

**強度**：第 1～7 節除標「單案」者外皆為**預設**（個別裁定者之慣例，曾於不止一個專案沿用）：專案已有文件之格式、禁詞表與格式要點者從專案（專案參數第 21、25 項）；與專案現有文件之格式（如中英夾雜、表格之用法）衝突之條目不套用；專案無任何格式依據時採用本節，並於回報註明。有固定字面者宜入 lint（〈落地到專案〉），lint 之方法見 skill[role-writer-validate] 之《文句與因果審閱》§2。第 7 節之轉檔語法與第 8 節為工具用法，已對自有套件之原始碼、說明文件與實跑查證。

## 1. 文體

- 系統開發報告是平實精要之事實陳述，不是小說、宣傳或行銷；每句以承載事實為唯一目的。
- 確定語氣：建置、提供、現已可、目前最新版之。
- 用詞平實，不用文學性或比喻性之詞。
- 一律台灣用語，不用大陸用語。讀者一看即知非本地撰寫。
- 書面語不以「有」接動詞：「亦有新增」寫「亦新增」，「現亦有進行重構」寫「現亦已重構」（「有進行」連用時，「進行」一併省去）。

## 2. 標題與段落

- 標號後接簡短標目，內文另起新行，對應層級之 Markdown 標題。
- 章之最高層用一般中文數字（一、二、三），不用壹、貳、參；小標下之分段編號用（1）（2）或 A、B，不跳回（一）（二）。標題不截短至失去原意。
- 成果以段落敘述，不用要點小標，不用段中粗體。
- **條列只用於短項**（每條純文字約 80 字以內，經驗值），條列之下不接圖；長文與圖文改段落。
- 章節交叉引用以名稱為之，不寫「詳見第 X 節」。「如後」只指同一節內緊接之段落或下一節（「茲分述各系統之成果如後」）；所指在更遠處者以章節名稱交代，要呈現畫面者於該處配圖並寫「如{圖}所示」，否則刪去。why：「其畫面詳如後」指向數節之後，讀者在下方找不到，只能一直往下翻。
- 段落不以「並、且、及、又」開頭，不以純阿拉伯數字開頭。
- 條列各系統時一系統一條目，不合併。

## 3. 標點

| 項目 | 規則 |
|---|---|
| 全半形 | 中文標點全形；英文詞組內部半形（「（Long-Term Support, LTS）」） |
| 分號 | 一句至多 1 個，只區分同一事之常態與例外或主語相同之兩段；不串接多項目或要點；主語不同者改句號，新句須有主語並以表明關係之詞承接 |
| 冒號 | 段落之中不用；只留於段尾帶出緊接之條列、表格或圖表；「所示」之後不用冒號 |
| 破折號 | 不用，改逗號、「即」「其中」「係」或分點 |
| 括號 | 小括號不塞多項並列或 12 字以上之長內容（縮寫定義除外）；成對符號左右相等 |
| 引號 | 畫面文字、按鈕、欄位、文件名一律「」；【】〔〕『』《》只限標題類，內文不用。並列之「」之間仍以頓號相隔、末項以「與」接（依序為「館藏」、「借閱」、「預約」與「統計」），「」不代替頓號；名稱本身含「與」「及」者，末項亦以頓號並接「共 N 個」（〈章節與敘事〉第 2 節）；標籤接值不是並列（「排序」為「依到期日」） |
| 提及符號 | 冠以名稱（「以引號「」標示」），不單寫空的成對符號 |
| 箭頭 | 內文不以 →、⇒ 傳遞概念，圖內連線不在此限 |
| 全形空格 | 不用（Word 顯示為方框） |
| 引圖表句 | 以「如{題名}所示」為引用短語；其後只可接同句之圖內說明（線型、圖例、舉例，見〈亮點與配圖〉第 5 節），句號收尾；「如下」與「如{X}所示」一句只用一種 |
| 範圍（單案） | 以「至」連接，與英數之間留半形空白（「第 1 至第 3 層」「10 至 20 冊」），不用「～」「〜」；逐字引用之畫面文字照原文；圖內文字同 |

## 4. 數字與字串

- **計數**用阿拉伯數字＋半形空白＋量詞（2 個、8 至 16 碼）；章節標號、序數、慣用語（單一、統一、一律、進一步、二維、三維）不在此限。
- **年度**寫明起訖，不寫「以前」；紀年依專案參數第 16 項。
- **按鍵**與**使用者須照打之字串**置於「」內。
- **「以○○為例」**置於例子之內容前；例子只是動作之對象或輸入值者直接寫入動作。
- **格式名**全大寫（JSON、CSV、TXT、XML、PDF、PNG）；專有名詞依官方寫法（Markdown、Excel、Node.js、npm）。帶點之副檔名、程式碼、畫面原文不在此限。
- **程式代號**不入報告，以中文通稱；照錄之提交紀錄不改寫。專案以編號體系（規則、決策、案例編號）追溯者，可依專案裁定在不影響敘事之處保留編號。

## 5. 縮寫與全稱

- **一切簡稱於該報告正文首次出現處以全稱定義**，封面不算。「本報告」等自指詞亦屬簡稱，首次寫報告名＋（以下簡稱本報告）。
- **技術縮寫**首次以「中文（English, ABBR）」定義，之後只寫縮寫；分冊各自計。一般讀者皆知者（API、HTML、PDF、IP）免定義；查無全名者附其格式或標準之名稱。
- **委託單位給定之名稱與系統全稱，名稱中間不插入括號英文**（不把內部詞之英文插進全稱）；內部詞之英文只於該詞單獨出現處定義。系統本身之英文名依〈章節與敘事〉第 6 節於開場附於全稱之後，專案另有裁定者從專案。
- **系統名不簡省**；同一對象全文同名；並列全名。
- **過度縮減之自創短語不用**：單獨拿出來讀者看不懂者改寫（此類問題之審閱見 skill[role-writer-validate] 之《文句與因果審閱》§8 通讀問題表「缺字與歧義」）。

## 6. 用字判斷法

專案之用字裁定（禁詞、正名、畫面元素名稱）一律以專案為準，本節不替專案選字。

**判斷法**：①此詞於本專案有無既定用語，先查權威來源（已審文句、共用資料、功能要點、程式與畫面），不憑印象；②念給不寫程式之讀者聽，對方能否從字面知道意思；③此詞之定義是否合於此處之事實（專有名詞寫系統實際所用之那一個，不以上位總稱代替）；④相接之詞語是否同類。

**一詞一義**：報告內已固定用於某類事物之詞，不移用於另一類。例：「更新」用於軟體、資料與資訊（執行環境升至長期支援版亦屬更新）；設備（主機、硬碟）之汰換寫「設備更換與升級」，前後對比寫「更換前」「更換後」，描述效益時以「系統之優化配合設備之更換與升級」表述，不寫舊設備之不足。畫面與法規之既定用語照錄。照抄專案文件之表述前，先查該詞於報告內是否已有他義。

**功能以功能本身命名**：摘要、圖名、節名與圖內文字以功能本身之名稱寫，不以其中一項操作或展示效果代稱，也不借用其他領域之術語；能力以使用者得到之呈現命名（「並排比較 2 個分館之借閱統計」），不以達成它之操作（「可拖曳分隔線」）簡稱。首次詳述處寫出其內容。操作手冊之步驟照實寫動作與畫面反應，那是操作，不是功能之名稱。why：以一項操作代稱整個功能，讀者以為只多了該操作，把功能讀小。

**兩岸用語**：代碼依語意寫程式碼或代號；數據庫寫資料庫；服務器寫伺服器；默認寫預設；信息寫資訊；軟件寫軟體；視頻寫影片。台灣亦通行者（優化、渲染、數據、日誌）不改。畫面原文照錄者，經查證後放行。簡體來源稿之整批轉換可用 skill[convert-chinese]，轉後仍須逐段判讀。

**開發端行話改為讀者看得懂之說法**（規格書類附錄描述程式介面時，通用術語照用；下表僅示意，專案畫面與規格既有之用語優先）：

| 行話 | 報告寫法 |
|---|---|
| 軟刪除 | 將資料標示為無效 |
| 切片上傳 | 分段上傳 |
| 入庫 | 寫入資料庫 |
| 熱重載 | 自動重新載入 |
| 冪等 | 重複執行不會重複登錄 |
| 降級 | 改以靜態呈現 |
| 以專案、程式專案、版本庫稱組成 | 系統、子系統（〈專案參數表〉第 8 項） |

## 7. 圖題與表題之文體

md 端為轉檔所寫之語法（圖表自動編號與交叉引用、`data-for` 標記、留白、欄寬、格內換行）依 skill[role-writer-report-convert-to-docx] 之 `references/md-syntax.md`。不以該轉檔管線產製者，圖表編號與交叉引用依專案之產製方式（無者以 md 手編並於回報註明），內建檢查（〈落地到專案〉第 4 節）之意旨仍適用。下列為屬報告文體之規則：

- **圖題**在圖下、末字為「圖」；**表題**在表上、末字為「表」；內文以編號引用，不寫「如下表」「如上圖」。
- **三欄以上才用表格**：兩欄改條列分項（表單類與指定版式除外）。
- **用表是為了逐項看**：一格內不列舉多項，一項一列（系統與其組成之表，每個組成 1 列，上層名稱與數量跨列合併；合併之語法依 skill[role-writer-report-convert-to-docx]）。介紹組成之段，項目多時直接帶出表，文字與表二選一，不各寫一遍。

## 8. docx 產製與驗證

md 轉 docx 之轉檔呼叫、環境、範本與範本衛生、執行紀律（一次一個、產製期間不開文書軟體）、docx 驗證（實體檔、document.xml 文字節點核對）、審稿順序與產物管理，一律依 skill[role-writer-report-convert-to-docx]，本技能不重述。
