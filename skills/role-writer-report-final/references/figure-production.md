# 產圖規範

適用於報告內**自繪結構圖**（流程、架構、層級、構面與時程圖）：報告端之規範與自有套件之用法。畫面截圖之選用見〈亮點與配圖〉；**亮點展示圖**（固定畫布、HTML 排版輸出 PNG 之主張圖）之版面、配色與製作歸 skill[role-design-web-for-showcase]，不在本檔。圖之來源是否含自繪依專案參數第 23 項。第 1 節之通則與圖內文字之規定，對亮點展示圖同樣適用（該技能亦要求圖內文字與報告共用同一份用字規則）。

**自有套件名稱不入報告與圖內**（專案參數第 26 項之預設，報告主體即該套件者依該項之例外），圖數據檔之註解不在此限。

**版本不寫死**：下列用法已對自有套件之原始碼、說明文件與以虛構內容之實跑查證；文中標「實測」者為以虛構內容實跑所得之示例，數值隨套件版本而異。使用前仍以專案實際安裝之 `node_modules/<套件>/` 之 README 與 `src/` 為準，版本不同時以實查為準，下列程式碼可先以虛構內容在專案內小跑一次確認。專案未安裝之套件不自行加裝，先依專案之產圖要點；要新增工具時請裁定者同意；專案無此工具且不得新增時之退路見〈亮點與配圖〉第 3 節。套件本身之問題依自有套件之通報管道，不在專案端繞道。

## 1. 共通原則

- **圖內文字即正文**：節點名、條目與邊標籤同受全部用字與禁詞約束；用字只有一份，報告、圖、簡報不各記一套；寫法（湊字之詞組、列一般技術、寫格式不寫內容）依〈文句與段落診斷〉第 1 節。盤查時須含圖數據（盤查方法依 skill[role-writer-validate]，圖內文字另依其 L2 逐張開圖）。
- **節點必對應實際實體**：不畫無對應實體之虛構節點或同一實體之分身；每張圖之節點與連線以程式或文件核實，依據、線型語義與色彩寫於圖數據檔之檔頭註解。
- **名稱不硬編**：系統與單位之名稱取自共用資料檔。
- **一圖一數據，改數據不改渲染器**：圖數據與繪圖引擎無關；渲染問題依自有套件之通報管道回饋套件端。
- **節點順序即語意順序**：同層節點依陣列序排列，順序不可隨意。
- **圖內不畫圖名**（預設）：圖名由報告之圖題提供。
- **單主題單線型，虛線過多即分拆**：一張圖同時承載兩種主題致實虛線混雜時，拆為單主題圖；繪前先查證各元素之歸屬。
- **線型語義必須交代**：實虛線併用者於引用該圖之句、引圖短語之後交代（〈亮點與配圖〉第 5 節），或報告設標示慣例一節；兩者皆無則改全實線。僅單一線型者不附說明。
- **色彩語義固定一組**：一份報告內同色同義；紅色保留給錯誤與異常終態，不用於一般節點。專案可定義各色之意義。

## 2. 版面：報告是 A4 直式

以下數值屬**版式參數**（以報告內圖之最大顯示寬度 700px 為例，專案版式不同者依其版式重算）。

- **流程與架構圖優先上下排（TB）**：橫圖入報告受版面寬壓縮，字過小。線性流程節點再少亦 TB。
- **扇出過寬不改 LR**：依既有分群收斂為富節點（標題＋條目）或拆為多層；LR 只限 TB 與收斂皆不可行者，理由註記於圖數據檔。
- **寬高比以 4/3 為界**：大於 4/3 者列為候選，由人判讀；墊寬過之小圖看繪圖本身。時程圖本質扁長（列少時寬高比可達 5 以上），不適用此判準。
- **群組內無連線之成員會橫排並撐寬整圖**（實測示例：成員 3、6、9 個之寬高比約為 1.5、2.7、3.9）：成員達 4 個以上時改為一個節點、成員列為條目；不用假連線直排（會虛構先後順序）。
- **收窄後仍寬逾 2000px 者拆圖**（經驗值，依版式）：被拆部分於原圖縮為 1 個節點並於標題指向另一圖；判定扇出之多個終態可改為 1 個節點之條目。
- **訂新規則或改標籤後回掃既有圖**：以程式量全部圖之寬高比。
- **最小圖寬墊寬**：報告內圖以固定最大寬度顯示，窄圖會被放大，圖內文字甚至超過內文。圖寬小於最小圖寬時左右對稱透明墊寬，內容不縮放，白底下看不見；html 與 docx 兩端同一比例。放進文書檔之畫面截圖（手冊用圖、標準圖、掃描工具之截圖）亦同：於複製至報告之圖夾時墊寬，不改來源圖本身（測試比對不需要最小圖寬）；同一張圖於各報告一致（成果報告直接沿用手冊之墊寬圖）。截圖之最小圖寬取寬版截圖中較窄者，定值前量文書檔內之實際顯示尺寸，細節依 skill[role-writer-report-e2e-to-manual] 之 `references/content-pipeline-contract.md` §6。

```js
// minW = 設計字級 × 解析度倍數 × 顯示寬 ÷ 目標字級
// 示例(版式參數):流程圖節點字 14px、2 倍、顯示寬 700、目標字級 14 → 1400;要點字 21px → 2100
import sharp from 'sharp'
async function padFigWidth(buf, minW) {
    let m = await sharp(buf).metadata()
    if (m.width >= minW) return buf
    let left = Math.floor((minW - m.width) / 2)
    return await sharp(buf).extend({ left, right: minW - m.width - left, background: { r: 0, g: 0, b: 0, alpha: 0 } }).png().toBuffer()
}
```

- **docx 不降採樣**：過寬之圖在 docx 內不被降採樣，靠範本之旗標，作法與檢查依 skill[role-writer-report-convert-to-docx] 第 4 節。

## 3. 圖種之選型

圖種之選用判斷（流程圖、層級樹、放射圖、六邊形圖、甘特圖，與畫面圖、亮點展示圖之取捨）在〈亮點與配圖〉第 3 節。本檔只管選定後之作法。要點：有先後或資料流向才用流程圖；並列之面向畫成流程圖會虛構順序；主題多者不硬塞一張。

## 4. 工具用法

**共通**（三個圖類套件皆同）：

- 回傳 PNG Buffer，以 Playwright 之 Chromium 渲染；匯入走套件官方入口（`import X from '<套件名>'`）。
- 圖內字型固定為微軟正黑體；未安裝時退回無襯線字型，字形會不同，須於 Windows 或已安裝該字型之環境產製。
- **連線需求**：流程圖之 p10 產線自 CDN 載入 elkjs；層級樹之 p2 與甘特圖自 CDN 載入繪圖庫，產製時須可連線；放射圖、六邊形圖與層級樹之 p1 不須連線。流程圖之主 README 未提連線需求；舊文件若寫「斷網可用」，以實測為準。
- **靜默回退**：下列輸入錯誤不會報錯而是套用預設，須開圖確認：流程圖之 `dir` 非 `'LR'` 一律當 TB、未知 `cls` 回退為 blue、`fromSide` 大小寫錯被忽略；層級樹之 `mode` 非 `'p2'` 一律當 p1、`boxStyle` 只作用於 p1、`nodeWidth`／`width`／`height`／`compact` 只作用於 p2；圖示名查無時只畫「?」。

### 4.1 流程圖

```js
import WFlowchart from 'w-flowchart'
let buf = await WFlowchart({
    dir: 'TB',
    nodes: [
        { id: 'A', label: '讀者送出借閱申請', cls: 'blue' },                          // label 可含 \n；過寬自動斷行
        { id: 'G', label: '申請處理階段', cls: 'greenG', align: 'center' },           // 群組：cls 以 G 或 G2 結尾；align 為 top、center、bottom
        { id: 'B', title: '申請檢核', items: ['證號狀態', '可借冊數'], cls: 'green', group: 'G' }, // 富節點
        { id: 'D', label: '檢核通過？', cls: 'diamond' },                            // 判斷節點
        { id: 'E', label: '建立借閱紀錄', cls: 'orange' },
        { id: 'F', label: '顯示未通過原因', cls: 'red' },
        { id: 'N', label: '通知館員', cls: 'purple' },
    ],
    edges: [
        { from: 'A', to: 'B' },
        { from: 'B', to: 'D' },
        { from: 'D', to: 'E', label: '是' },
        { from: 'D', to: 'F', label: '否', fromSide: 'R' },                          // fromSide、toSide：L、R、T、B（大寫）
        { from: 'F', to: 'N', kind: 'dashed' },                                      // kind: 'dashed' 為虛線
    ],
})
// 預設產線為 p10；WFlowchart(inp, { output: 'svg' }) 取 SVG 字串（p1~p8 與 p10 支援，p9 不支援）
```

- **色票**：一般節點 blue、green、orange、purple、red、done；判斷節點 diamond；群組 blueG、blueG2、greenG、greenG2、orangeG、purpleG。
- **`align`、`fromSide`、`toSide` 只有預設產線支援**，且只見於該產線之說明（套件主 README 之範例未列）。
- **判斷節點**：進自頂部頂點，預設主要出口自底部頂點，另一結果自側邊頂點（`fromSide`）——此為套件說明所載。
- **側邊出口之目標排序（經驗法則，套件說明未載，實測可重現）**：`fromSide: 'R'` 之目標於 `nodes` 陣列須排在底部出口之目標之後（`'L'` 反之），否則連線繞回並交錯。
- **菱形隨文字加大**：長標籤以 `\n` 斷為 2 行；條件多或無另一條處理線者，改為富節點之條目，不另立菱形。
- **回邊改變佈局**：圖內有循環時，起點可能被排到側邊（併用群組時實測可重現，起點被排到圖之左下），判斷之側邊出口也可能與底部出口交錯，改接第一個處理節點未必能解（套件說明已列「斷環點不一定讓起點落最上」為已知限制）。開圖確認；不合者拿掉回邊，以邊標籤或條目表達（如「否，回報錯誤，修正後重送」）。
- **群組與跨群邊**（經驗，未逐項重現）：多數節點分屬群組且邊跨群時，來源節點可能被排至底部並繞行，改為不用群組、以顏色區分；邊穿過群組標題時，把邊接至群組本身。
- **標題過長**（經驗，未重現）：富節點之標題列可能於字中斷行，標題改寫中文名稱，長識別字列為條目。

### 4.2 層級樹、放射圖、六邊形資訊圖

```js
import WInfographic from 'w-infographic'
// 放射與六邊形同一份輸入
let inp = {
    center: { title: '借閱\n服務' },
    items: [
        { label: '查詢', icon: 'mdi:magnify', notes: ['館藏檢索', '預約排隊'] },
        { label: '借還', icon: 'mdi:book-open-variant', notes: ['線上續借'] },
    ],
}
await WInfographic(inp, { type: 'circles', startAngle: -45 })  // type 必給；預設 startAngle -90 為正上方，順時針
await WInfographic(inp, { type: 'hexagon' })                   // items 可加 side: 'left'、'right'

// 層級樹
let tree = { tree: { title: '借閱平臺', subtitle: '組成', children: [
    { title: '前端', desc: '畫面與互動。', cls: 'blue', children: [{ title: '共用組件', cls: 'teal' }] },
    { title: '後端', items: ['服務', '排程'], cls: 'green', icon: 'mdi:server' },
] } }
await WInfographic(tree, { type: 'hierarchy' })                     // 預設 p1 色帶版式
await WInfographic(tree, { type: 'hierarchy', boxStyle: 'card' })   // p1 卡片版式，不顯示 items
await WInfographic(tree, { type: 'hierarchy', mode: 'p2', compact: true, nodeWidth: 226, width: 680, height: 880 })
```

- **`opt.type` 必給**（`circles`、`hexagon`、`hierarchy`），缺漏即拋錯。
- **色票**：blue、green、teal、orange、purple、red、gray；circles 另可給 `#rrggbb`（六位）；hexagon 配色固定，不看 `cls`。
- **圖示**：`mdi:名稱`（kebab-case，取自本機依賴，不連網）或 `<svg` 開頭之 SVG（須在字串最前面）。
- **限制**：hexagon 每側至多 5 項，超出即拋錯；只要有一項給了 `side`，未給或寫錯者全歸左欄；`notes` 與 `items` 須為陣列。
- **層級樹之寬度**：p1 兄弟一律水平展開，寬度隨葉數線性成長；在 700px 顯示時，經驗上可讀之上限約總寬 1800 CSS px（第二層約 6 組帶說明，或葉節點約 8 欄）；更寬者用 p2 之 `compact` 收摺。p2 之畫布留白由套件裁切，呼叫端不必再裁。

### 4.3 甘特圖

```js
import WGanttchart from 'w-ganttchart'
let buf = await WGanttchart({   // 單一參數，無 opt
    axisStart: '2030-01-01',
    axisEnd: '2031-01-01',
    rows: [
        { id: 'a', label: '規劃', start: '2030-01-01', end: '2030-04-01', cls: 'navy' },
        { id: 'b', label: '開發', start: '2030-03-01', end: '2030-10-01', cls: 'azure' },
    ],
})
```

- **色票**：navy、azure、sky；未給或查無一律 azure。**日期**：嚴格之 `YYYY-MM-DD`（須補零且為真實存在之日期）；`id` 為字串且不可重複（重複即拋錯）；`label` 必填。
- **時間軸**：主軸為西元純年份，細格一季，細格標籤為「1月、4月、7月、10月」。
- **橫條不帶文字**（套件行為）：橫條內不繪製任何文字，列名畫在圖左側之欄位，圖上沒有日期文字。各列起訖與繳交時點由報告內表格陳述，表格與圖自同一份數據衍生，表圖必一致（此為本技能之使用建議）。
- 列落在時間軸外會被裁切；全部落在軸外時逾時拋錯且不指明原因，須先核對日期與軸範圍。

## 5. 產製流程

1. 改圖數據（不碰渲染器）。
2. 繪圖：各報告之產圖程式依圖數據輸出至報告之圖夾，並印出尺寸與寬高比。
3. 檢視：確認為 PNG（檔頭魔術數字），逐張以原尺寸目視（字是否被截、節點順序與群組歸屬、邊標籤、連線是否交錯）。
4. 重產報告：docx 內嵌圖，圖變必重產。產圖與產文分離，圖穩定且繪製較慢。
5. 跨報告沿用：既有圖先產，再由引用者複製；同一主題之兩張近似圖不並存。
