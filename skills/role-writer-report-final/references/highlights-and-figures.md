# 亮點與配圖

本檔管**挑什麼亮點、用哪一類圖、圖從哪來、放哪裡、怎麼引用、圖名**。自繪結構圖之作法見〈產圖規範〉；亮點展示圖之版面、配色與製作歸 skill[role-design-web-for-showcase]；畫面圖之產製歸 skill[role-writer-report-e2e-to-manual] 與標準圖產線。門檻與來源依專案參數第 23、24 項。規則強度標示見 SKILL.md 第 2 節；未標者按預設處理，數值（字數、張數）為經驗值，依專案調整。

## 1. 基本規則

- **有亮點就有圖**：審查委員看圖才有印象，只有文字之亮點等同沒寫。只配架構圖而無實機畫面者不合格。
- **差異與亮點分開**：差異一律以文字精簡陳述，判定為亮點者才配圖。**刪亮點不等於刪差異**：裁定者說某項不算亮點，刪的是配圖與地位，文字仍保留，除非明說刪文字。
- **一般操作與小改不算亮點**（預設）：刪除、基本編修、查詢條件之縮小、前期已有而本期小改者，以及程式內部優化，不配圖。
- **沒有畫面者免配圖**：後端機制以文字重點陳述；資料流複雜而文字不易掌握者，可配流程圖。資訊安全一節多以文字敘述。
- **成果報告是重點報告**：每項亮點 1～2 張最能呈現功能本身之圖；確認框、成功訊息、點擊前之中間階段不選，那些屬手冊；提示本身即為功能者（如衝突提示、拒收提示）不在此限。
- **無新進度之系統不硬湊亮點**。

## 2. 亮點之挑法

| 報告 | 怎麼挑 |
|---|---|
| 分年 | 本期相對前一期之新功能與重要調整；對照前期之報告與圖判斷，以圖為證不憑記憶 |
| 全期 | 先列各系統之主要目的與主要功能，自主要功能中挑最能體現目的者；分年之細部改版，只有本身即主要功能者才選 |

- **全期總報告之基本款（單案依據，須專案參數第 24 項明示要求才套用）**：每個重要系統至少一張基本款——重要系統指讀者會直接操作之主要系統，後端無畫面者免；讓讀者看到這個系統平常呈現什麼資料（項目內容、主頁、主要清單），只有進階功能之圖不合格；圖名寫明內容，不以「主頁圖」籠統帶過。沒有要求者不因此補圖。分年報告只挑本期之新功能與重要調整，不因此替前期已有之功能配圖。
- **登入、存取紀錄與事件監控**：屬本期範圍者可考慮列亮點並寫明用途；是否列入依專案參數第 24 項。只寫能力，可寫所防範之風險，不宣稱能完全阻擋某類攻擊。
- **下載類功能**：圖含開啟下載檔後之畫面，看得出能力者優先。
- **只放本部署所用之功能**。
- **產出亮點清單先審**：系統、亮點、配圖（圖名與檔名）列表；另登記「考慮過而未選」與理由，下次不必重判。

## 3. 圖之類別、來源與選型

先判斷要表達什麼，再選類別；類別之能否使用依專案參數第 23 項。

| 要表達 | 圖類別 | 來源與製作歸屬 |
|---|---|---|
| 功能本身（畫面） | 畫面圖 | 操作手冊用圖或測試標準圖，沿用其檔名以便回溯；產製歸 skill[role-writer-report-e2e-to-manual] 與標準圖產線 |
| 委託單位或專案既有、已審之設計圖 | 官方圖 | 內容已涵蓋者優先沿用，不另自繪近似之圖 |
| 流程、資料流、系統架構、前後端分層 | 自繪流程圖 | 〈產圖規範〉：有先後或資料流向才用 |
| 組織關係、功能分解、由上而下之構面 | 自繪層級樹 | 同上 |
| 一個中心、並列之面向 | 自繪放射圖或六邊形圖 | 同上；並列面向畫成流程圖會虛構順序 |
| 階段與時程 | 自繪甘特圖 | 同上 |
| 單一主張之成果總覽、成效示意（版面經設計之展示圖） | 亮點展示圖 | **本技能只決定要不要做、放哪一節、圖名與引用句；版面、配色、標題、圖內文字之檢核與 PNG 之製作歸 skill[role-design-web-for-showcase]**。專案參數第 23 項未允許者不做 |

- **分工與觸發**：只問「挑哪些亮點、配哪幾張圖、圖名」用本技能；要做或改亮點展示圖本身用 skill[role-design-web-for-showcase]；兩者並用時先由本技能定亮點清單與圖名，再交該技能製作，製作完成後回本技能之逐張開圖檢查（第 4 節）。
- **手冊沒有該功能之圖，不以臨時截圖替代**：代表當初漏了；依序補規格、測試與標準圖、手冊，再更新報告。標準圖之新產或重產須依專案與全域之授權規定先取得授權。專案無此條產線時，依專案參數第 23 項決定。
- **無繪圖工具時**（專案未安裝所需之自有套件且不得新增）：依專案之產圖要點；專案無產圖要點者，圖類只取官方圖與畫面圖，自繪結構圖先問裁定者是否新增工具，不以手寫近似圖充當；無法詢問時（如非互動執行）不繪該圖，改以文字敘述該結構，並於完工回報列為「需你決定」。
- **畫面圖取自經審定之來源**，不取舊說明書，不臨時截圖。
- **只放當期畫面**（預設）：不放前一期之畫面作新舊對照。新舊並列會讓審查者比較差異，看見原本未被注意之問題。差異以文字敘述。
- **判斷**：主題多者不硬塞一張；一張圖只承載一個主題。

## 4. 逐張開圖檢查（以原尺寸）

| 項目 | 要看什麼 | 不合時 |
|---|---|---|
| 紅框與圖名 | 紅框落在功能本身，不是連帶結果；圖名依紅框所標命名 | 換圖或改名 |
| 測試字樣 | 圖內無「e2e」等測試字樣 | 回測試端把輸入值改為一般字樣，重產下游 |
| 測試環境之異常 | 日期跳動、假時鐘、逾時紅字、預設值為 0 等 | 換不受影響之圖；整批皆受影響者（如固定種子日期）依專案裁定處理，不自行改種子或時鐘 |
| 可辨讀 | 紅框所標之元素看得清楚 | 不選 |
| 文字一致 | 圖所呈現者於引用段說明，文字與畫面相符 | 改文字或換圖 |

本部署未列之功能若出現在畫面上（如入口連結），該圖亦不選。標準圖有多語版本者，依報告語言選同語版，只檢查入選之圖。逐圖目視是 skill[role-writer-validate] L2「截圖真的打開看」在成果類之具體項目。

## 5. 文圖之排列（預設）

- **短段收攏，圖集中**：同一主題之連續短段合為一段，各小段以「如{圖}所示」收尾，小段之間以「此外，」「而」「於○○之處，亦可」銜接，圖依引用順序集中於段後。讓讀者能一路讀文字，要看圖再往下找。
- **各自配圖者**：一段很長（約 250 字以上）或主題獨立（架構 2 圖、瀏覽之後之編修）。
- **引圖句是段落最後成分**：「…如{A}所示，…則如{B}所示。」首個引圖句之後不接內容句（合併段則逐小段判斷）。不為圖單獨成段；拿掉引用短語後要有實質內容。
- **條列之下不接圖**。
- **連續多圖之間加空段落**，避免前圖之圖題與下一張貼近。
- **文為主圖為輔**：提及呈現方式時語序以文在前、圖在後，或逕述內容；不寫「以圖為主」（〈內容邊界與防禦性寫作〉第 7 節）。
- **同圖之線型語義**：實線與虛線併用者於引圖句前一句交代；單一線型者不附說明。

## 6. 圖名（預設）

- 末字為「圖」，全報告不重複。
- 不冠年度；分年可寫「○○重構後之主頁圖」，全期不寫改版後、重構後。
- 圖名與引用短語完全一致。
- 不夾帶案例編號、英數代號。
- 展示資料之性質標示依專案參數第 14 項（需標示者圖名與引用句皆標，資料本體寫「測試用○○」，統計類補說明，純表單與工具列不加）。

## 7. 主題型圖組（單案依據）

章節要求呈現某主題之圖（作業流程、介面關係等）時，不拿單一例子充當整體：

1. 先定義該主題於本系統之範疇。
2. 逐一對照全部對象歸類，明列哪些要講、哪些不講、哪些可合併，取捨理由寫入內文。
3. 每類配圖或明示不配圖。先想好架構，再定圖之張數。
