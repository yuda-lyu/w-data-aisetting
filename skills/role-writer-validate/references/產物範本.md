# 產物範本（報告驗證）

每一層檢查都必須留下下列其中一種產物；產物放在 `./tmp/`（或使用者指定的專案 docs 目錄）。欄位可以增加，不可以減少；**表上不可以有空白格**——填不出來就是那一格還沒驗證，狀態欄寫「未驗」。

範例列中引用的檔案與行號取自實際安裝的 `w-dispatch-ai` 1.0.19（`node_modules/w-dispatch-ai/`）與 Codex CLI 0.149.0，2026-08-30 核對；其他版本行號可能不同。標示「示意」或「虛構內容」的列不是真實專案，只示範欄位與寫法。

**判定值**（每句必填其一，不留空；非「已證」者必填處置）：

| 判定 | 意思 |
|---|---|
| 已證 | 現行程式（與必要的 diff）支持全句 |
| 事實錯 | 與現行程式或紀錄不符 |
| 範圍不符 | 有這件事，但數量、全稱或對象寫錯 |
| 查無依據 | 程式、diff 與文件都找不到；須寫明查過哪些路徑與關鍵字 |
| 目的或效益無依據 | 改動屬實，所接的目的或效益由機制看不出來 |
| 期間不符 | 明確不屬報告所述期間；或改動屬實，但其所接之效果前期已成立（效果層，SKILL.md Step 3「效果亦須為本期才有」） |
| 期間無法確認 | 改動屬實，但發生於版本庫首筆提交之前而無紀錄（不判錯） |

處置：改寫（附新句）／改成推測語氣並加註「需實測確認」／刪除。「已證但值得知悉」欄記錄不算錯但可更精確的地方（例：某值實為設定常數，不是實測值）。

帳冊抽查：挑數列（含已證列）回程式複驗，在帳冊末記列號與結果；抽查通過不等於其餘已證列已驗。

## 6. 覆蓋聲明（回報末尾必附）

```

- L0a 實體存在：已做，N 項——存在 a，修正 b，刪除 c（./tmp/validate-entities.md）
- L0b 需求對齊：已做，需求 N 條——已回應 a，刻意不回應 b（理由見矩陣），漏列 c 已補
- L1 主張溯源：已做（抽樣 §x／全量），主張 N 句——判定值各幾列（已證 a，事實錯 b，範圍不符 c，查無依據 d，目的或效益無依據 e，期間不符／期間無法確認 f）；處置——改寫 g，改推測 h，刪除 i；帳冊抽查 j 列
- L1b 文句與因果審閱：已做，候選 N 筆（改 a，不改 b 附理由）；審閱者 k 名（新 context），讀取範圍、未讀範圍；回報 N 條——採用 a，未採用 b（理由見帳冊）／未做（原因）／不適用（理由）
- L2 實跑：已做，N 項——一致 a，差異 b 已處置
- L3 反向覆蓋：已做，盤點 N 項——已寫 a，刻意不寫 b，漏列 c 已補
```
